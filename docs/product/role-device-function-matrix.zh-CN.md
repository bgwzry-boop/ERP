# 岗位、设备与功能权限矩阵

> 状态：已确认的产品基线
> 更新日期：2026-07-18
> 适用范围：完整 ERP 目标形态与原材料第一阶段上线
> 依据：已确认的岗位分工、设备条件、决策权限、收款核销、原材料、出库和设备维护规则

## 1. 结论

手机端不复刻桌面端，也不把桌面左侧菜单和右侧详情等比例缩小。

- 同一岗位在 PC 和手机上共享同一套业务数据、状态、权限、版本号和审计记录，但界面按使用场景重新组织。
- PC 负责完整录入、批量处理、全局调度、复杂核对、可信打印和管理；手机负责现场任务、扫码、拍照、提醒、决策和即时确认。
- 每个手机岗位进入独立岗位首页，首页先回答：`我现在要做什么 / 做到哪一步 / 下一步点哪里`。
- 办公室 A/B 在 PC 上能看到所有现场任务队列并负责协调，但“看得到、能催办、能处理异常”不等于可以代替现场人员完成报工、打包、出库或送达。
- 管理审批权与系统录入权分开。办公室可以代录，但不能因此获得妈妈、阿姨或老板的决策权。
- 每人一个正式账号、一个本人设备；不共用账号，也不共用前线设备。所有写操作记录实际操作人。

## 3. 各岗位详细功能

### 3.1 办公室 A/B

两人是同权限的通岗和互备关系，不拆成“订单专员、仓库专员、对账专员或打印专员”。两人各用本人账号，进入同一个共享任务池。

#### PC：完整办公室工作台

1. 今日工作
   - 公共待办、超时、异常、急单、今天要发。
   - 打开对应订单、库存、出库、对账或原材料记录。
   - 查看任务当前处理人、占用状态、备注、下一步和历史。
2. 订单
   - 订单识别、人工复核、草稿保存、正式确认、订单池查询。
   - 订单优先级和排期建议准备、证据整理、提交经营决策。
   - 订单变更、取消、缺货和生产异常协同。
3. 库存与交付
   - 库存查询、预留、释放、盘点差异草稿和授权确认流程。
   - 创建出库指令、打印纸质出库单、交库房、跟踪备货和实物出库。
   - 派车/自提/物流交付、司机任务、交付证据和异常处理。
4. 对账与收款
   - 对账单预览、发送、收款登记、差异提交和核销流程。
   - 支付宝/微信到账通知与客户群打款消息或截图匹配。
   - 精确到账可按既定权限登记结算；少付时只登记实际到账，余款保持未结，等待妈妈批准或驳回抹零。
5. 生产、打包与打印
   - 查看和协调丝印、制袋、打包任务队列。
   - 生成/调整调度，处理现场异常，打印出库单和标签，管理可信打印任务与设备。
   - 现场人员的实际报工、打包完成、实物出库仍由对应本人手机提交。
6. 原材料
   - 送货单图片/PDF OCR、逐行人工核对、一卷一标、标签打印、贴标核对。
   - 原料库存、供应商月度 Excel 对账、异常和采购建议查看。
7. 基础资料与上线状态
   - 在授权范围内维护客户、价格、规格、库存、员工和机台。
   - 查看岗位账户就绪、打印设备和上线阻塞。

#### 手机：聚焦伴随端

- `当前任务`：工单/待办处理、订单异常提醒和快速回到相关记录。
- `原材料收货`：`拍送货单 -> OCR 结果逐行核对 -> 标签预览 -> 选择已批准蓝牙打印机 -> 提交打印 -> 确认成功/处理失败 -> 贴标`。
- `待处理`：打印失败、需要补拍、待复核、待重新打印和交接给另一名办公室人员的记录。
- `全部功能`：只列该手机场景需要的功能，不复制完整 PC 菜单。

手机点击“打印”不等于打印成功。服务器必须保存打印机身份、作业状态、回执、失败原因、重试和作废关系，安全重试不得重复生成有效标签。

### 3.2 老板

老板使用第三台 PC，保留完整管理与财务能力：经营总览、客户对账、财务核验、正式核销、重大异常、权限/账户和系统状态。老板与妈妈可以处理重大异常。

V1 不建设老板完整手机端；若未来增加，只做必要提醒和少量高风险确认，不把第三台 PC 的完整工作台缩小搬到手机。

### 3.3 妈妈与阿姨

两人不能使用电脑，直接 ERP 决策必须全部在专用手机端完成。页面围绕“待我决定”组织，而不是围绕 ERP 模块组织。

每张决策卡至少显示：为什么需要决定、订单/客户/数量/金额、当前影响、办公室说明、图片或聊天证据、建议方案、可选结果和历史决定。主要按钮为 `同意 / 退回 / 要求补充信息`。

| 决策事项 | 妈妈 | 阿姨 | 老板 |
| --- | --- | --- | --- |
| 订单优先级 | 可决定，主要 | 可决定，备份 | 管理查看；必要时按管理权限处理 |
| 生产排期、插单、重排 | 可决定，主要 | 可决定，备份 | 管理查看；必要时按管理权限处理 |
| 客户对账差额 | 可决定，主要 | 可决定，备份 | 财务/管理查看与正式处理 |
| 抹零 | 可决定，主要 | 可决定，备份 | 查看正式结算结果 |
| 出货数量差异 | 可决定，主要 | 可决定，备份 | 查看和异常升级 |
| 重大异常 | 可决定 | 无权限 | 可决定 |
| 原材料采购 | 查看系统每日建议和依据；保留经营判断 | 备份查看/协助 | 查看成本、资金和执行结果 |

同一事项只记录一个实际决定人。第一个有效终态决定生效；另一台手机若持有旧版本，提交必须被阻止并刷新。办公室代录时必须同时记录业务决定人、系统操作人、决定渠道、决定时间、录入时间、内容和证据，代录不产生审批权。

### 3.4 原材料经手人

手机/PDA 流程固定为：

`扫码一卷 -> 显示颜色/规格/宽度/重量/供应商/入库来源 -> 选择目标机台或区域 -> 确认发料 -> 成功反馈`

- 扫到不可用、已发出、标签不清或信息不一致的卷，进入异常，不允许静默继续。
- 第一阶段原材料发料不要求订单号或生产任务号，避免为了系统流程虚构关联。
- 杂工为默认经手人；实际需要时，可给指定印刷工人同一条受限扫码权限。

### 3.5 丝印、制袋与打包

三类岗位均为手机执行、办公室 PC 调度。手机首页只显示本人/本机当前任务和待处理队列。

- 丝印/制袋：任务详情、开工、当日合格数、异常数、固定异常原因、继续生产或暂停等确认、完工和成品照片。
- 打包：待打包任务、货品核对、实际数量、包数、标签状态、打包完成和异常。
- 生产当日报数、生产完工和打包完成均为高风险写入：提交前展示任务、客户、货品、实际/计划数量、异常数或包数以及会改变的业务记录；确认期间冻结原字段和重复提交。

### 3.6 成品库

1. 办公室创建出库指令并成功打印当前纸质出库单。
2. 打印成功后，任务立即出现在成品库手机上。
3. 库房可以先按手机任务找货、拣货并登记`已备货`。
4. 拿到纸质出库单后，核对手机任务、纸单版本和实物规格/数量。
5. 全部一致才可提交`实物已出库`。
6. 若纸单 500、实物 430，提交`数量不符`：不扣库存、不改订单、不生成对账结算，自动进入办公室待办。
7. 办公室/授权管理人员选择：`按实际数量出库 / 补货后再出库 / 赠送数量 / 暂停等待确认 / 作废本次出库指令`。
8. 选择按实际数量或赠送数量后，状态变为`差异已确认待重新出库`，原纸单变为`待重新打印`；必须打印、接收并重新核对新的当前纸单后才能出库。

系统必须分开记录：办公室出库指令、纸单版本、手机任务可见、已备货、纸单核对、实物出库、最终提货/送达。

### 3.7 司机

手机按任务阶段显示：`待装车 -> 已装车/去送货 -> 到场 -> 交付确认`。

司机提交送达前，确认摘要必须展示任务、客户、货品、预计/实际数量、包数、照片/回单、收货人和纸单状态。返回修改不能上传附件，也不能提交完成。

### 3.8 现场机修/技术人员

手机工作台包含：

- 扫码/选择设备，查看当前报修、巡检和保养任务。
- 记录故障分类、照片、检查结果、处理动作、换件/用料、是否恢复、完成时间和实际技术人员。
- 无法恢复时标记停机或等待配件，并通知办公室影响的生产任务。
- 办公室查看和协调相同状态，但不代替现场技术人员填写实际维修结果。

## 4. 跨端关键流程

### 4.1 原材料收货与打印

`办公室手机拍单 -> OCR -> 人工逐行核对 -> 一卷一标 -> 蓝牙可信打印 -> 贴标核对 -> 原材料经手人扫码发料`

PC 可继续处理同一批数据、月末供应商 Excel 对账和异常；手机与 PC 不是两个独立台账。

### 4.2 生产与打包

`办公室排队/协调 -> 工人手机报工 -> 异常回办公室/管理 -> 打包手机完成 -> 办公室打印/交付`

### 4.3 成品出库

`办公室出库指令 -> 纸单打印成功 -> 库房手机任务可见 -> 提前备货 -> 收到当前纸单 -> 三方核对 -> 实物出库 -> 客户/司机/承运人接货`

### 4.4 收款、抹零与正式核销

`支付宝/微信到账证据 + 客户群消息/截图 -> 办公室匹配并登记实际到账 -> 精确到账按规则结算 / 少付保持余款 -> 妈妈手机决定是否抹零 -> 系统生成独立抹零决定 -> 正式核销与审计`

音响提示只能帮助办公室注意到收款，不单独作为长期到账证据。

### 4.5 原材料采购建议

每天下班前，服务器按可信库存、追踪消耗、需求范围、安全上下限和数据充分性生成建议，并按供应商分组。办公室查看依据后，对每个厂家采购群执行一次复制并手工发送。

建议的生成、复制和群内发送都不是正式采购单，也不自动扣增库存或形成供应商承诺。系统分别保存建议输入、范围、置信度、复制人、目标群和后续人工确认。

## 5. A/B、多人决策和跨端冲突规则

1. 打开可编辑记录时可建立可见、限时的编辑占用，显示`谁正在处理、从何时开始、何时释放`。
2. 其他人可只读查看，但不能静默覆盖。
3. 确需接手时使用`申请接手/强制接手`，记录原处理人、接手人、原因和时间。
4. 每次提交携带当前版本号；版本过期返回冲突并要求刷新，不能采用后写覆盖前写。
5. 决策类事项采用“第一个有效终态决定生效”，后续旧页面提交失败。
6. 未完成草稿、备注和下一步必须保留，支持办公室 A/B 显式交接。
7. 移动端和 PC 端使用相同冲突规则，不能因为手机操作简化而跳过版本校验。

| 办公室手机蓝牙可信打印 | 业务规则已定，真实链路未完成 | 取得实际打印机品牌/型号和手机系统后，选择厂商 SDK、原生桥或受支持浏览器能力；不能用前端点击冒充成功 |

当前代码还存在一个明确角色混用：`warehouse` 默认进入`原料扫码`。目标必须拆成“原材料经手人”和“成品库人员”两个入口、两组权限，不能继续共用一个 warehouse 手机首页。

## 7. 开发优先级

### P0：原材料第一阶段上线

1. 办公室手机完成送货单拍照/OCR/人工核对/标签预览。
2. 对接实际蓝牙标签打印机，完成服务器可信作业、失败和安全重试。
3. 原材料经手人手机/PDA 完成逐卷扫码发料和异常。
4. 每人账号、本人设备、权限收窄和操作审计。
5. 第一阶段生产前端只暴露原材料相关入口，其他域保留代码但隐藏。

### P1：现场和决策闭环

1. 妈妈/阿姨经营决策手机端。
2. 成品库出库手机端和纸单版本门禁。
3. 现场机修/巡检/保养手机端已完成代码闭环；保留正式账号、实际机台、相机和弱网真机验收。
4. 丝印、制袋、打包手机页按岗位拆分并做真机验收。
5. 将办公室现场完成类操作从默认主流程中移除，只保留调度、异常处置和有审计的应急代录。

### P2：经营辅助自动化

1. 每日原材料采购建议、供应商分组和一键复制。
2. 老板 PC 的经营与重大异常汇总优化。
3. 在确有使用需要后，再评估老板手机上的少量高风险提醒，不做完整 PC 镜像。

## 8. 尚需现场输入，但不属于未确认业务规则

业务分工和端侧边界已经足够进入设计与开发，不需要再次向用户重问岗位功能。只有实现真实硬件时需要补充技术参数：

- 办公室手机系统与版本。
- 蓝牙标签打印机品牌、型号、标签尺寸、厂商 SDK/协议和是否支持状态回读。
- 原材料经手人使用普通手机、PDA 还是蓝牙扫码枪。

这些参数决定接入方式，不改变本文已经确认的岗位权限和业务流程。
