# ERP 完整业务逻辑基线

最后更新：2026-07-16

本文件是当前项目的完整业务总纲。它描述目标业务事实、人员分工、终端边界、状态转换和审计原则，不表示现有代码已经全部实现。与历史需求中的`六端齐备`、`管理人员直接操作 ERP`、`库房手机任务池`、`独立财务电脑`等假设冲突时，以本文件和最新《Decisions》为准。

## 1. 项目定位与范围

ERP 服务单工厂的线上线下一体经营，核心不是单纯进销存，而是把以下业务闭环连起来：

`客户需求 -> 订单审核 -> 库存/生产 -> 打包 -> 纸质出库 -> 自提/送货/物流 -> 客户对账 -> 收款核销`

原材料、供应商对账、价格、员工机台、打印、待办、附件和审计是主链的支撑域。

V1 优先完成可人工控制、可回退、可审计的核心闭环。企业微信自动读群、自动采购/排产、路线优化、完整工资、完整售后责任和订单级人工成本放到后续阶段。AI 首阶段只做只读经营异常雷达，不直接修改订单、库存、生产、采购或财务事实。

## 2. 厂区人员、设备与职责

### 2.1 三台电脑

| 设备 | 固定使用人 | 业务范围 |
| --- | --- | --- |
| 办公室电脑 1 | 办公室综合岗 A | 全部办公室业务、打印 |
| 办公室电脑 2 | 办公室综合岗 B | 与 A 完全相同的全部办公室业务、打印 |
| 第三台电脑 | 老板回厂时使用 | 经营查看、客户对账、财务核对、正式收款/核销、重大异常和最终管理 |

当前没有生产管理、库房或专职财务电脑。老板使用同一套桌面 ERP 外壳，通过账号权限显示管理和财务能力，不另造一套管理系统。

### 2.2 角色与终端

| 角色 | 当前终端 | 核心职责 |
| --- | --- | --- |
| 老板 | 第三台电脑 | 管理、客户账、财务确认、重大异常和最终确认 |
| 母亲、婶子 | 当前不直接操作 ERP | 订单先后、生产、采购、账单查看、授权范围内抹零等经营决定 |
| 办公室综合岗 A/B | 两台办公室电脑 | 录单、审单、排产代录、库存、原材料入库、采购记录、打印、出库指令、账单准备、异常跟进 |
| 丝印工 | 手机 | 领取任务、开工、照片、印刷数量、异常 |
| 制袋工 | 手机 | 机台任务、开工、每日/最终合格数量、机器动作数、照片、异常 |
| 杂工/领料人员 | 扫码枪或 PDA，必要时手机 | 原材料扫码领料、机台/任务选择、部分领料、余料退回 |
| 打包人员 | 手机或 PDA | 任务领取、产品核对、实际数量、包裹、标签异常、完成打包 |
| 库房/成品出库人员 | 纸质出库单 | 找货、规格数量核对、实物出库和交接、差异反馈 |
| 司机 | 手机 | 装车核对、配送、水印证据、收货人、异常和完成送货 |

生产大屏未来如配置，只是公共只读终端，不是岗位，不做排程、审批或录入，也不是 V1 上线前置条件。

### 2.3 办公室 A/B 岗

- 两人权限相同、互为备份，各自使用独立账号。
- 两台电脑都有完整办公室功能和打印能力。
- 订单、入库、排产、出库、账单、打印和异常进入共同任务池，不按模块永久分人。
- 系统记录实际提交人；未完成事项保存状态、备注、最后操作人和下一步动作。
- 同单并发编辑必须有编辑占用、乐观版本校验或明确冲突提示，禁止静默覆盖。

### 2.4 决定人与操作人

经营决定与系统录入是两个事实。办公室代录母亲、婶子或老板的决定时，必须保存：

- 业务决定人；
- 认证系统操作人；
- 决定方式：当面、电话、微信、纸面或其他；
- 决定时间和系统录入时间；
- 决定内容、原因、授权范围和必要凭据。

抹零、价格调整等金额事项还要保存原金额、调整金额和授权依据。代录不会让办公室自动获得经营审批权限；超出授权范围的事项进入老板待确认。

不直接登录 ERP 的人员仍在员工主数据中作为决定人或实物执行人留痕，不为了形式化角色虚构终端或共享账号。

## 3. 核心业务对象和不可混用数据

主要对象包括：客户与联系人、来源消息、订单草稿、原始订单、订单明细、价格快照、库存项、库存占用、库存流水、生产任务、排程、报工、异常、打包任务、包裹、出库/交付任务、纸质单据版本、交付证据、对账单、收款、原材料入库单、卷/件档案、领料、消耗、余料、供应商对账、待办、附件和操作日志。

原始订单保留一次客户下单行为和汇总；订单明细才是生产、库存、打包、交付和对账的主状态对象。

以下数量分别保存，永不互相覆盖：

- 客户下单数量；
- 库存预留数量；
- 丝印实际数量；
- 制袋合格数量；
- 机器动作/循环数；
- 打包数量和包裹数量；
- 库房实物出库数量；
- 客户实际交付数量；
- 计费数量；
- 赠送/不计费数量；
- 异常、损耗或待处理数量。

## 4. 订单到正式执行

### 4.1 订单来源与识别

办公室可手工输入自然语言订单、粘贴客户消息或处理后续批量识别结果。每一组原始客户消息独立留痕；不同客户不能合并到同一草稿。

系统尝试识别客户、产品类型、尺寸、袋色、提手色、印色、印刷面、印刷内容、数量、交付方式和备注。低置信字段形成持久化审核项，未明确接受或修改前不得正式确认。

库存询问、临时留货、取消和正式订单是不同意图：

- `有吗`加数量只是待客户确认的库存询问，不锁库存；
- 明确`要/留/算上`才推进订单或临时占用；
- `有的话给我留 N`形成有到期时间的临时占用；
- 正式确认后的追加需求创建新的原始订单，不回写历史订单。

### 4.2 正式确认

正式确认前服务端重新检查客户、生产必填字段、低置信审核、准确库存、价格和客户风险。

确认后：

- 保存客户、地址、交付方式和价格快照；
- 现货明细创建准确库存预留；
- 定制/需生产明细原子创建生产任务和履约占位；
- 缺货明细单独等待、取消或补货，不阻塞其他可执行明细；
- 后续改动按订单阶段走变更、作废重打或异常流程，不覆盖历史。

## 5. 成品库存

成品库存按产品/尺寸、工厂颜色、提手类型、成品款式、库区和状态准确匹配；近似颜色或尺寸只能提示，不能算有货。

库存区分实物在库、已预留、可用、已备货/待提货锁定、车间报数待复核、在途、待处理和报废。任何数量变化必须来自库存流水，不能直接修改总库存。

主要流水来源是生产入库、订单预留/释放、库房实物出库、客户交付、退回、盘点更正和报废。库存更正使用草稿、证据和高风险确认，写入库存、流水、待办和审计。

## 6. 原材料采购、入库和领料

采购决定由母亲、婶子或老板作出，办公室记录决定人、供应商、需求、预计数量/重量、时间和依据。供应商到货后进入实物入库：

`现场拍送货单 -> OCR 草稿 -> 办公室逐行审核 -> 按实物卷数建档 -> 一卷一标签 -> 打印 -> 人工与实物一对一核对贴标 -> 正确卷逐卷入库 -> 异常卷隔离`

供应商单号可空；ERP 入库号、明细号和卷/件号必须生成。OCR、标签打印或签单附件都不能直接生成可用库存。

正确卷进入`已贴标/可用库存`；不一致卷进入`标签或实物不符/待确认`；整单允许`部分入库，N卷异常`。异常卷可单独作废/重打标签并再次确认，不影响正确卷。

手机/扫码枪不参与逐卷扫描入库门禁。办公室人员用手机打开原材料时，使用独立轻量`原材料收货`表面，只显示`拍单 -> 核对 -> 打印 -> 贴标`、当前单据和一个下一步动作；详细 OCR 字段只在主动进入复核时展开，库存查询、供应商对账、成本/毛利、机边领料和密集历史仍留在桌面端。后续领料时，杂工扫描卷标签，校验可用状态，选择生产任务、机台和整卷/称重部分领料；材料转为`机边领用`。部分领料保留来源卷剩余量并创建机边子卷追踪。

消耗分整卷、部分消耗；余料退回先进入`余料待复核`，复核重量和库位后才恢复可用。领料本身只改变追踪和库存位置，不直接生成成品、客户应收或毛利。

## 7. 排产和生产执行

母亲、婶子作出生产先后、插单、采购等业务决定，办公室在桌面生产工作台代录排程、机台、日期、顺序和决定证据。草稿排程只有办公室可见；发布后车间手机端才看到任务。

丝印流程：领取/锁定任务 -> 开工 -> 调试/必要照片 -> 填报实际印刷数量 -> 完成或异常。

制袋流程：查看本机任务 -> 开工 -> 必要成品图 -> 报当日合格数量 -> 跨日累计 -> 报最终合格数量 -> 进入库存/打包下一步。

机器动作数只作过程证据，不等于合格产量、库存、交付数量、计费数量或计件工资。每日进度不产生库存、占用、打包和对账；最终报工经过高风险确认后才产生相应业务结果。

生产异常必须选择固定原因和`继续生产`或`暂停等确认`。暂停只暂停任务并阻止继续报工；处理决定由经营/生产决定人作出，办公室回录决定人与操作人。异常处理本身不能静默改变库存、对账或收款。

## 8. 打包和标签

打包人员用手机/PDA领取任务，核对客户、产品和可打包数量，填写实际打包数量、包裹数、每包数量和必要重量，反馈数量或标签异常。

打包完成是高风险动作，确认前显示计划/实际数量、包裹、标签和对订单/履约/待办/追踪的影响。包裹合计形成打包事实，但不等于客户已经收到，也不能提前生成应收。

标签和单据有版本、作废和重打记录。预览、进入队列、发送打印机和可信打印完成是不同状态；浏览器自报`已打印`不能推动正式业务。

## 9. 成品出库和交付

### 9.1 纸质出库指令

办公室确认待出库明细，生成并打印两联出库/自提/送货单，记录单据版本、打印状态和交给库房的时间。`已打印`只代表出库指令准备完成，不等于实物出库。

库房按纸单找货、核对规格/数量、完成实物出库和交接。正常或异常结果通过当面、电话或纸面标注反馈办公室；办公室回录纸单、库房实物执行人、认证操作人、反馈方式、执行时间和录入时间。

出库至少区分：

1. 待打印/待交库房；
2. 待拣货/已备货；
3. 库房实物已出库；
4. 司机在途或物流待确认；
5. 客户最终已交付；
6. 数量不符/无法出库/退回等异常。

已备货只锁定库存。库房交给司机后货物进入在途且不可再次销售，但司机成功送达后才形成客户交付事实和对账候选。自提客户或物流实际拉走时，实物出库与最终交付可在同一时点完成。

### 9.2 三种履约方式

- 自提：办公室打印自提/出库单 -> 库房按纸单交货 -> 提货人签字或留下交接事实 -> 办公室确认最终交付。
- 司机送货：库房把货和单据交司机 -> 司机手机核对包裹并确认装车 -> 配送 -> 水印照片/可选签单 -> 办公室复核证据；装车异常退回办公室/库房，司机不能改单或重打。
- 快递/快运：办公室打印标签和出库资料 -> 库房/打包放入待提货区 -> 实际拉走后由办公室根据现场事实确认；待拉走阶段只锁库存，不生成正式交付。

数量不符时，库房不能直接改单。办公室先回录差异，再根据客户和经营决定选择少发并取消剩余、先发部分后补、等齐再发或取消；旧纸单作废，新数量重新生成并打印，订单、库存、交付和对账保留完整关联。

## 10. 客户对账和收款

客户对账以最终实际交付事实和交付日期为基础，不以订单、生产、打包或纸单打印日期为基础。

系统始终分开本期应收、本期已收、本期未收、历史欠款和累计欠款；实际交付数量、计费数量和赠送数量分开。金额使用订单价格快照、计费数量和有审计的调整计算。

办公室准备/发送对账单、登记客户确认和付款截图/收款音响等到账线索。到账线索不能自动核销。正式收款确认、核销、重大差异和超授权抹零由老板在第三台电脑或另行明确授权的登录账号完成。

少付进入差异待确认，可转未收欠款、授权抹零或账单更正；多付转预付款、退回或冲历史欠款。任何处理都不能静默清零。母亲、婶子的远程经营意见由办公室代录决定人和证据，但不能冒充正式系统核销人。

## 11. 供应商对账和付款

供应商月度账单导入后，与已确认的原材料入库记录按供应商、单号/批号、日期、规格、颜色、卷数、分卷重量、单价和金额匹配。低置信匹配只推荐，必须人工复核。

流程为：`供应商账单导入 -> 预检/匹配 -> 办公室复核 -> 对账确认 -> 应付草稿 -> 老板/财务付款确认`。供应商账单不能反向制造原材料库存或覆盖已确认卷重量；客户应收和供应商应付属于两个独立账域。

## 12. 主数据、待办和审计

主数据包括客户/联系人/地址、产品尺寸颜色提手、价格版本、原材料/供应商、员工、角色、机台/车间、交付与结算方式、打印设备和模板。历史订单保留当时快照，后续主数据变化不覆盖历史。

办公室共同待办池保存当前事项、业务对象、等待时间、状态、备注、最后操作人和下一步动作，不默认抢单或永久分配。待办必须引用真实且类型匹配的订单、库存、生产、交付、对账或原材料对象。

正式数据不物理删除，使用作废、关闭、更正、重开和版本记录。高风险动作必须先显示对象、数量/金额、业务影响，冻结来源输入，再明确确认；取消不发送写请求。认证身份来自登录会话，浏览器请求体不能选择操作人。

## 13. 当前业务基线后的实施顺序

1. 以本文件建立模块业务事实表：参与人、入口、前置、状态、输出、异常和审计字段。
2. 对照现有页面、接口、状态机、权限和上线门禁，统一列出与本基线不一致的问题，不立即边查边改。
3. 重点审计办公室 A/B 并发、决定人/操作人双留痕、纸质出库状态链、原材料入库门禁、可信打印和收款确认权限。
4. 问题清单确认后再分 P0/P1/P2 修正并验证真实电脑、手机、扫码枪和打印机。

现有 D49 服务端八角色正式账号就绪门禁在本轮保持权威：不得因终端分工调整而删除、绕过或降低该发布门禁，seed 账号仍不计入覆盖。角色账号就绪与日常主要终端是两个概念；如以后需要改变八角色门禁，必须作为独立业务和发布决策重新确认，不能在本轮界面/流程改造中顺手修改。
