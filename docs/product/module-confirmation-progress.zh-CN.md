# ERP 模块确认进度表

最后更新：2026-07-05

本文档用于防止重复追问。后续继续细化需求前，应先查看本表：已经确认度较高的模块，不再围绕小细节反复问；未确认项集中成批询问，采用“问题 + 建议 + 原因”的方式让用户批量判断。

## 防重复追问规则

- 后续提问前，必须先看本表的 `已确认范围` 和 `已基本确定，后续不要反复问的小模块`。
- 表里已经写入 `已确认范围` 的内容，不允许换一个模块名重复问。例：`车间报数库存可以直接出库` 已属于成品库存/出库口径，不应在机边直出模块再次问是否可以出库。
- 对确认度 `90%` 以上模块，后续只允许问落地材料：页面字段、按钮权限、初始数据、阈值、模板、设备、真实表格、API/ERD。不再问主流程是否要这么走。
- 对确认度 `80-89%` 模块，后续只问剩余缺口，不再重问主流程。
- 对确认度 `75%` 以下模块，才可以继续做较完整的批量需求确认。
- 每次继续问问题时，应先输出一句 `本模块已确认：...；本次只问剩余未定：...`，避免重复。

## 进度口径

- `90-100%`：业务规则基本稳定，可以进入页面、字段、接口、原型细化；除非影响金额、库存、权限、客户沟通或员工操作负担，否则不再追问小问题。
- `75-89%`：主流程已确定，剩少量阈值、模板、现场数据或实施细节。
- `50-74%`：方向明确，但还需要实际表格、现场数据、主数据或规则口径。
- `50% 以下`：只确认了方向或后续版本目标，不适合直接进入开发。

## 已基本确定，后续不要反复问的小模块

- 一个客户一次下单生成一个原始订单，下面拆订单明细；生产、库存、打包、履约和对账主要按明细流转。

## 下一阶段必须集中补齐的问题池

### A. 页面、权限、状态枚举和 API，优先级最高

1. 待补齐：数据库 ERD 图、字段类型、索引设计、真实页面原型和真实模板/样例数据。
   建议：页面字段、主按钮、状态枚举、API/数据库边界、ERD 落地规则和验收测试场景已经基本落地，下一步收集初始主数据和真实模板，或者直接开始把 ERD / API 合同写成开发文档。
   原因：继续问页面小字段会重复；开发前更需要真实模板、初始数据、ERD/API 合同和可执行的验收记录。

### B. V1 落地必须有初始主数据，不再问业务方向

1. 待补齐：按已确认字段和导入规则生成实际 Excel 导入模板文件，并导入一批真实样例数据。
   建议：先生成客户、颜色、尺寸/成品款式、初始库存、机台产能、员工账号、供应商/原材料批次模板，在测试环境跑一次预检查。
   原因：字段口径和导入策略已确认，下一步不是继续问业务方向，而是拿真实数据试导入、查错误行和缺字段。

2. 待补齐：安全库存和目标库存初始值。
   建议：V1 先按精确库存项人工填；没填的库存项不自动预警，只做销量统计。系统跑 7/15/30 天销量后再给调整建议。
   原因：预测要靠历史数据，第一版不能假装智能，也不能把未维护主数据误报成缺货。

3. 待补齐：每台制袋机每个常用尺寸的大概产能。
   建议：先填一个粗略产能表，允许后续根据报工自动校准。
   原因：预计完成时间、补货建议、排产预警都依赖产能。

### C. 打印模板和现场纸张需要尽快定

1. 待补齐：用户提供现有针式打印单据模板、对账 Excel 样式和快递/快运标签纸实物尺寸。
   建议：按现有针式打印纸张做出库/自提/送货单模板，按实际标签纸做快递/快运包裹标签。
   原因：字段和规则已定，真正风险在针式打印对齐、连续纸行高、文字截断和标签纸尺寸。

2. 待补齐：快递/快运标签纸尺寸和打印机。
   建议：V1 先只支持一种标签模板，但必须按实际纸张测试。
   原因：标签内容已经确定，真正风险在纸张尺寸、打印清晰度、截断规则。

### D. 生产与成本还有现场数据缺口

1. 待补齐：逐台确认制袋机计数器是当天计数、累计计数，还是两者都有，以及是否每天清零。
   建议：欧诺机口径先按机器动作次数记录；现场确认每台机读数类型后，再决定日报取机器日报值还是用上下班累计差值。
   原因：计数器不是成品数量，但会影响产能、过程差异和损耗分析。

2. 待补齐：特殊型号、新工艺、覆膜等是否有不同折边/接缝/克重/提手规则。
   建议：先按已确认默认常数走，特殊项进入人工确认表。
   原因：不能把成本公式写死，否则后面利润测算会错。

3. 待补齐：油墨、辅料怎么计价。
   建议：V1 成本先做布料和提手，油墨/辅料保留字段，等采购单据确认。
   原因：布料和提手是大头，辅料不清楚时不要拖慢主流程。

### E. 后续版本方向，不应继续占用 V1 讨论时间

1. 企业微信会话内容存档、客户群自动回复、OCR 自动匹配收款：方向清楚，但属于 V2/V3，需要技术和合规验证。
2. 工资自动核算：方向清楚，但必须等现有工资表和打卡机导出格式。
3. 深度成本和精确毛利：方向清楚，V1 先留数据，跑一段时间再确认毛利分摊；机台产能可等用户提供生产汇总单后再导入校准。
4. 动态支付码、商户接口、聚合支付：暂不优先。
5. 路线优化、复杂物流追踪：暂不优先。

## 后续提问规则

- 每次继续需求讨论前，先定位到本表对应模块。
- 确认度 `85%` 以上的模块，不再问低层小细节，除非影响金额、库存、权限、客户沟通、责任追溯或员工操作负担。
- 确认度 `75%` 以下的模块，采用批量问题，不要一条一条问。
- 批量问题格式固定为：`问题 -> 建议 -> 原因 -> 需要你判断的点`。
- 用户确认后，同步更新本表的确认度和未确认项，避免下次重复。
