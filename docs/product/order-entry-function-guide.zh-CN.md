# 订单录入模块功能说明

适用人员：办公室录单人员、管理人员、后续开发和交接人员。适用范围：电脑端的订单录入与正式报价工作台。

本文说明从客户来单到正式订单的操作方法、拆单规则、价格保护和异常处理。录单确认完成后，办公室仍需对每笔订单安排出库或生产排单。本文对应2026年10月25日拆单入口接入版，发布状态及验证记录见第六部分。

## 一 模块职责与业务流程

办公室是订单分流中心。微信群来单由办公室复制文字并录入，不自动读取群聊。小程序来单先形成待审核草稿，不能未经办公室确认直接成为正式订单。

正常操作顺序：粘贴原文 → 识别草稿 → 核对明细 → 必要时拆行 → 保存或生成正式报价 → 核对金额 → 普通确认或预览拆单后确认 → 到订单池排单。

| 对象 | 含义 | 对库存和生产的影响 |
| --- | --- | --- |
| 客户原文 | 本次录入或来单的文字依据 | 单独保存原文不构成正式接单 |
| 订单草稿 | 已识别、可继续核对的明细 | 未正式确认前不新增正式库存占用和生产任务 |
| 正式订单 | 办公室已确认接单的订单及明细 | 后台建立对应价格快照、交付任务，并按规则建立库存占用或生产任务 |
| 订单排单 | 办公室安排后续执行 | 确认下单不等于已排机、已出库或已交付 |

有库存的标准通货安排出库；缺货的标准通货安排生产。定制印刷通货、特殊尺寸空白袋、特殊尺寸印刷袋也要先排产。是否通货、是否有库存、是否印刷是不同事实，不能只凭印不印刷决定是否生产。

特殊尺寸按订单生产和交付，不因此新增普通通货成品库存。印刷合组是计价和生产协同关系，不等同于把原始订单合并或拆单。

## 二 识别和核对订单明细

打开订单录入，在“客户订单原文”中粘贴完整消息，点击“识别客户消息”。识别会建立服务器草稿，返回明细和草稿版本。原文可包含多种规格、颜色和交期，识别结果仍须人工核对。

示例：王五包装 30*38*10 红色40个 2099-11-02自提。示例中的客户和日期仅用于说明操作，应以真实客户档案和实际日期为准。

| 需要核对的字段 | 当前页面的操作方式 | 业务注意事项 |
| --- | --- | --- |
| 客户 | 明细标题显示识别结果 | 当前页面没有独立客户选择控件；未匹配时核对客户档案及原文后重新识别 |
| 订单分类 | 选择标准通货、印刷通货、定制印刷通货、特殊尺寸或外来袋印刷 | 分类决定后续业务路径，不能仅按是否印刷推断 |
| 规格和袋身颜色 | 直接修改输入框 | 规格按宽、高、侧核对；颜色不能与印刷色混用 |
| 数量 | 填写正整数 | 不能用小数下正式订单，也不能把机器动作数当成袋子数量 |
| 提手和是否印刷 | 在当前行选择 | 定制印刷另核对印刷内容、印刷面及印刷颜色 |
| 交付和需要日期 | 分别选择或填写 | 自提、送货、快递快运和日期是正式拆单的重要依据 |
| 加扣等特殊要求 | 在对应行核对 | 特殊要求会影响报价，不能只留在口头说明中 |

修改影响订单或价格的内容后，原正式报价失效，必须重新生成。识别置信度不足的字段仍受后台人工核对规则约束；修改字段不能冒充跳过服务器审核。

小程序草稿保留客户提交时的规格、数量和锁价。当前页不允许把锁价明细任意改写或拆成新明细；需要变更时应走已有正式业务流程。

## 三 拆分明细和拆成独立订单

“拆分明细行”和“按客户/交付拆单”是两个不同动作。拆成两行不代表已经生成两张订单。

| 操作 | 入口与结果 | 典型用途 |
| --- | --- | --- |
| 拆分明细行 | 每行下方点击按钮，原行数量先对半分为两行，奇数时第一行多1个 | 同一货品需要分不同数量、交付方式或日期核对 |
| 按客户/交付拆单 | 页尾打开后台拆单预览，核对后明确确认生成多张订单 | 不同客户、原始来单组、交付方式或最晚要货时间需要独立订单号 |

例如5000个先拆成2500个和2500个，可按真实来单再调整为3000个和2000个，并分别填写交付安排。拆行后数量合计应由办公室复核；拆分动作本身保持原合计，后续人工改量可能改变合计。

数量不足2个、非整数、已取消明细、留货转单绑定明细及小程序锁价明细，不提供自由拆行。留货绑定要求保留原数量和来源，避免一条留货被重复转单。

拆行会使旧报价失效，并清除原行的授权本单改价输入。其他费、增减额等不能自动复制到两行；应按实际分配重新填写并重新报价，其他未拆行的改价输入保留。

正式拆单按“客户、原始来单组、交付方式、最晚要货时间”组合分组。颜色、规格、是否印刷或当前库存不同，不直接构成独立订单条件。例如同一来单的1000个今天自提、2000个明天送货，可拆成两张；同一来单、同一客户和交付安排下的不同颜色，仍可是一张订单的多行。

预览显示每张订单的客户、交付和日期、明细、数量及按正式报价核对的金额。只有一个组时会提示无需拆单。缺必要信息或仍有待核对字段时不能确认。未生成正式报价时，可查看分组，但需返回报价后再确认。

点击“返回修改”或按Esc关闭预览，不创建正式订单；修改后需要重新报价及预览。点击“确认生成N张订单”后，后台统一写入多张订单并保留同一草稿来源，不允许只成功一半。网络回执不确定时保留原请求重试，不再次建立新单。

## 四 正式报价和价格保护

核对明细后点击“生成正式报价”。右侧显示每行袋子单价、印刷单价、计费数量、其他费、增减额和本次合计。识别产生的预估金额不能代替正式报价。

| 场景 | 当前规则 |
| --- | --- |
| 普通办公室订单 | 使用服务器核验的现行发布价或符合条件的材料成本报价；缺价时保留草稿并提示，不自动以零元成交 |
| 授权本单议价 | 只有有权限的账号可启用，填写实际单价或费用及原因；只作用于本次业务，不改全局价格表 |
| 全部赠送 | 通过明确的赠送选项和书面依据处理，不能以缺价冒充赠送 |
| 小程序来单 | 保留提交时的锁价版本和价格快照，不套用后续新价覆盖历史成交价 |
| 同内容同尺寸印刷 | 在当前报价规则允许时合计数量计阶梯价；不同内容或尺寸分别核算 |
| 同批补单 | 关联同客户、同内容、同尺寸且尚未开印的原单，填写同批标识及补单依据，后台复核真实执行情况 |

补单可能修订关联原单价格。右侧会逐条展示旧金额和修订后金额，必须逐项勾选确认；普通下单和拆单确认都提交同一报价编号及已确认原单清单。历史价格快照保留。

报价后再改数量、规格、颜色、交付日期、印刷信息或改价依据，须重新报价。报价、原单执行或材料价格已经变化时，后台可以拒绝旧报价，不能靠旧页面继续提交。

拆单预览的分组不重新定义计价规则。应先核对整份草稿的有效正式报价，再查看各组分配到的行金额；不能把预估总价当成最终金额。

## 五 保存确认和异常处理

| 按钮或状态 | 应怎样操作 | 结果及注意事项 |
| --- | --- | --- |
| 保存草稿 | 核对到一半可以保存 | 保存服务器草稿和版本；不等于正式接单或已排产 |
| 生成正式报价 | 明细齐全后核价 | 保存正式报价；核对每行及关联原单影响 |
| 确认下单 | 不需要独立订单号时使用 | 当前草稿生成一张正式订单，可包含多行及各自交付任务 |
| 按客户/交付拆单 | 确需多张独立订单时使用 | 必须先核对分组，再明确确认；不是直接一键建多单 |
| 结果待核对 | 网络超时、服务器错误或回执不完整 | 内容和导航保持锁定，只能按原内容重试；不新建另一份草稿替代 |
| 后台明确拒绝 | 按提示核对权限、版本或内容 | 输入保留；必要时重新读取、核价及预览 |

确认成功后，工作台显示成功回执，相关操作关闭，订单池等数据刷新。办公室随后逐单处理有货出库、缺货生产、定制排产等动作。确认下单不直接证明库房已拣货、司机已装车、客户已收货或财务已收款。

遇到客户未匹配、识别待复核、缺价、留货失效或版本冲突，应保留原文和草稿，根据提示处理。不要改用虚构客户、零价、估算库存或重复下单绕过校验。普通客户欠款不一概禁止下单；客户风险及授权规则由后台判断。

微信群内容仍由办公室主动录入。手机车间、司机和打包流程属于后续业务模块，本说明不把电脑录单页当成手机端下单入口。
