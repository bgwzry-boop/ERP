## 1. 硬性约束

### 1.1 允许改的文件

| 范围 | 说明 |
|---|---|
| `docs/prototypes/raw-material-roll-inventory-review/src/**/*.css` | 样式，随便改，但要遵守 1.4 |
| `docs/prototypes/raw-material-roll-inventory-review/src/**/*.jsx` | **只改结构和展示**：标签层级、class、布局包装、可见性、尺寸。不改 state、effect、事件处理里的业务调用 |
| `docs/prototypes/raw-material-roll-inventory-review/src/navigation.js` | 只允许改分组的 `label`、分组顺序。**不改任何 `id`、`allowedRoleKeys`、`permissionKeys`、`permissionPrefixes`** |
| `src/styles/tokens.css` | 可以新增 token；改已有 token 的值必须在 PR 里列出影响到的页面 |
| `scripts/check-*-ui.mjs`、`scripts/design-token-baseline.json` | 只能为本次改动新增检查或收紧基线，见 1.5 |
| `AGENTS.md` 末尾「Prototype-specific design decisions」 | 负责人拍板的设计决定，按已有格式追加一条 |

### 1.2 禁止改的东西

- `server/`、`shared/`、`db/`、`src/services/`、`src/domain/`、`src/lib/` 下的任何文件。需要后端配合的，写在 PR 里说明，由 Claude 来做（第 2 节 WP3 就是这种情况）。
- 接口地址、请求参数、返回字段的用法。
- 权限判断、角色可见范围、按钮能不能点的条件（`disabled` 的业务条件）。
- 路由和导航 `id`（20 个页面的 `id` 和网址一个都不能变）。
- 已有 `localStorage` 键的含义。需要换含义就用新键名（例如 `erp.pc.expandedGroups.v2`），读写都包 `try/catch`。
- 业务文案的意思。可以改排版，不能改话的意思。
- **不准加演示数据、假数据。** 测试站是负责人实测用的，空页面只做引导说明（见 WP7）。
- 不引入新的 npm 依赖、新字体、新图标库。图标用已经在用的 `@ant-design/icons`。
- 不整站换肤，不改深色侧栏和橙色主操作这两个品牌基调。

### 1.3 可见文字与测试

自动测试大量按「页面上看得到的文字」和「控件角色」找元素（例如 `getByRole("button", { name: "开单" })`）。

- 改任何用户看得到的文字、按钮名、`aria-label`、标题之前，先在整个仓库里搜这段文字：`grep -rn "要改的文字" scripts e2e review-e2e docs/prototypes/raw-material-roll-inventory-review/src`。
- 能不改就不改。必须改的，同一个 PR 里把对应测试一起改好，并在 PR 说明里列一张表：「原文字 → 新文字 → 改了哪些测试文件」。
- 不准为了让测试通过而删断言、放宽断言，或给测试加 `skip`。

### 1.4 视觉规则

- 不写裸颜色（`#xxx`、`rgb()`、`hsl()`），只用 `src/styles/tokens.css` 里的 token。`npm run design-tokens:check` 不得超过基线。
- 字号只用 token：`--erp-text-xs` 12px、`--erp-text-sm` 13px、`--erp-text-md` 14px、`--erp-text-lg` 16px、`--erp-text-title` 22px。**新写的样式不准用 11px（`--erp-text-xxs`）和 11.67px 这种小数字号。**
- 间距只用 `--erp-space-1` 到 `--erp-space-6`。
- 界面全中文，不出现英文单词、接口名、技术字段名。
- 1440×900、1280×800、1024×768 三个尺寸下都不准出现横向滚动条。

### 1.5 每个 PR 必须做到

1. 从最新的 `codex/staging-current` 拉分支，分支名 `codex/pc-ui-wpN-简短英文`。
2. **只开 PR，不合并、不部署**（见 `AGENTS.md`）。PR 的目标分支是 `codex/staging-current`。
3. 本地跑过并在 PR 说明里贴结果：
   - `npm run lint`
   - `npm run design-tokens:check`
   - `npm run review:check`
   - 改到的页面对应的 `*-ui.mjs` 检查
4. PR 说明里附上改动页面在 1440×900 和 1280×800 下的改前、改后截图。
5. PR 说明写清楚：改了哪些文件；改了哪些可见文字（1.3 的表）；有没有碰 1.2 里的任何东西（应该是没有）。
6. CI 全绿后通知负责人，由 Claude 审核。

## 2. 工作包（按顺序做）

### WP1 侧栏：内容不再被藏起来

**问题**（报告 #1、#8、#9、#11）：侧栏 20 项全展开，900 高的屏只露 14 项，下面整组看不见，也没有提示。当前菜单是橙色实底，和顶栏「新建订单」橙色按钮抢眼。

**说明**：办公室账号看不到「工资核算」「上线状态」（按角色隐藏），实际溢出比报告测的少一些，但管理账号确实会被藏。

**改哪里**：`App.jsx` 里的 `Sidebar` 组件和 `expandedGroups` 初始值（约第 333 行），`styles.css` / `brand-refresh.css` 里 `.pc-business-tree`、`.pc-nav-group*` 的样式。

**具体怎么改**：

1. **首次打开（没有保存过展开偏好）时只展开当前页面所在的那一组**，其他组折叠。现在的写法是全部展开（`return new Set(pcNavGroups.map(...))`）。
   - 用户手动展开、折叠后照常记住，继续用现有键 `erp.pc.expandedGroups.v1`，含义不变。
   - 已有的「切到折叠组里的页面时自动展开该组」（约第 478 行）保留。
2. **侧栏能往下滚时，底部显示渐隐遮罩和一行提示「下面还有 N 组」**。点这行提示，平滑滚到底。
   - N 按「整组在可视区以下」的分组数算。滚到底后提示消失。
   - 用 `IntersectionObserver` 或 `scroll` 事件判断，窗口大小变化要重新算。
   - 提示是 `button`，`aria-label` 写「还有 N 个菜单分组，点击查看」。
3. **折叠的分组头上显示待办数**：分组里有带数字的子项（目前只有「公共待办」）时，分组折叠状态下在分组头右侧显示同样的数字。
4. **当前菜单项改成左侧 3px 橙色竖条 + 浅色底**（用 `--erp-sidebar-hover` 一类的 token），文字加粗，不再用橙色实底。
   - `aria-current="page"` 保持不变。
5. 分组头加一个「全部收起」小按钮放在侧栏顶部品牌下面，不要做成每组一个。尺寸至少 32×32，`aria-label`「全部收起菜单」。收起时保留当前页所在组展开。

**不做**：「常用」置顶、拖拽排序、键盘方向键导航、面包屑。

**验收**：

- 清空 `localStorage` 打开任意页面，只有当前组展开。
- 1440×900 和 1440×768 下，用管理账号能看到底部提示，点提示能滚到「上线状态」。
- 当前菜单项是左侧色条样式，`aria-current` 还在。
- 现有导航相关测试全部通过（`npm run review:check`、`check-deep-link-auth-ui`、`check-route-guard-composition-ui`）。
- 新增 `scripts/check-pc-sidebar-ui.mjs`：断言首次只展开当前组；视口 768 高时提示出现，且数字正确；点击后最后一个分组可见。加进 `review:check` 末尾。

### WP3 客户档案：状态列显示错了，名单也不全（功能缺陷，要后端配合）

**问题**：

- 报告 #23：「状态」列显示的是对账状态（本期待对账 / 有欠款/差异），筛选也混进了对账状态。
- **报告没发现的更大问题**：客户名单是从「对账单 + 订单」拼出来的（`BusinessWorkspaces.jsx` 里的 `buildCustomerRows`），不是从客户资料读的。所以开单时新建的客户，下第一单之前在客户档案里根本看不到；停用的客户也分不出来。
- 报告 #33：右栏「编辑」只有 24×17，几乎点不到。

**分工**：

- **后端（Claude 做，先合并）**：在 `GET /api/master-data/customers` 加一个档案模式：`?scope=archive`。
  - 返回全部客户，包括停用的，最多 2000 条。
  - 每条字段：`customerId`、`name`、`shortName`、`contactName`、`phone`、`settlementCycle`、`status`（只有「正常」「停用」两个值）。
  - 外加 `total`。
  - 前端调用函数 Claude 会加在 `src/services/officeOrderApiClient.js`，名字叫 `listOfficeCustomerArchive({ authState, operatorId })`，返回 `{ source, items, total, blocked, error }`。
- **前端（DeepSeek 做，等 Claude 通知后端已合并再开工）**。

**前端具体怎么改**：

1. 客户档案的行改成以 `listOfficeCustomerArchive` 的结果为准。
   - 「当前应收」仍按 `customerId` 从对账数据里取，取不到显示「—」。
   - 只在对账单或订单里出现、档案里没有的客户，**不再显示在列表里**。
2. 列改为：**客户 / 客户编号 / 联系人·电话 / 结算周期 / 当前应收 / 状态**。
   - 「状态」只显示「正常」或「停用」，停用用中性灰，不要用红色。
   - 电话完整显示，不打码（办公室要打电话）。
3. 状态筛选的选项只有「全部 / 正常 / 停用」。
4. 对账状态放到右栏事实区，作为一行「对账：本期待对账」，旁边链接「去对账收款」（跳转用现有导航，不新增路由）。
5. 右栏「编辑」改成正常按钮，至少 32×32，样式和其他右栏次级按钮一致。
6. 读取失败时用现有的读取失败样式，保留已读到的内容。不要退回到旧的「对账单 + 订单」拼名单。

**不改**：客户资料编辑弹窗的字段和保存逻辑（`CustomerProfilePanel.jsx`、`CustomerAddressPanel.jsx` 里的业务调用）。

**验收**：

- 开单页新建一个客户后，客户档案里马上能搜到。
- 状态列和筛选里不再出现任何对账状态的词。
- 新增或更新 `scripts/check-customer-records-ui.mjs` 覆盖上面两点，加进 `review:check`。

### WP4 状态颜色：一眼分清轻重

**问题**（报告 #20）：黄色同时表示待出库、待对账、待收款确认、待打包；红色同时表示缺货和数量差异。现在的写法是按状态文字逐个写 class（`styles.css` 第 170 行附近的 `.status-可用` 等），没有统一规则。

**具体怎么改**：

1. 新建 `docs/prototypes/raw-material-roll-inventory-review/src/status-tone.js`，导出：
   - `statusTone(text)`：返回 `"blocked" | "todo" | "doing" | "done" | "neutral"` 之一；
   - `STATUS_TONE_TABLE`：全部映射。

   | 级别 | 含义 | 颜色 token | 例子 |
   |---|---|---|---|
   | `blocked` 阻塞 | 必须有人处理，否则流程走不下去 | `--erp-danger*` | 缺货、数量不符、送货异常、疑似重复、读取失败 |
   | `todo` 待处理 | 轮到某人做了 | `--erp-warning*` | 待出库、待打印、待对账、待收款确认、待打包、余料待复核 |
   | `doing` 进行中 | 正在做，不用催 | `--erp-info*` | 生产中、配送中、已备货、机边领用 |
   | `done` 完成 | 已经结束 | `--erp-success*` | 已交付、已结清、已确认对账、可用 |
   | `neutral` 其他 | 停用、已取消、草稿、未知 | `--erp-label-neutral*` | 停用、已取消 |

2. **把映射表做全**：在仓库里搜各页面实际出现的状态文字，全部归类。
   - 来源包括 `BusinessWorkspaces.jsx` 的各个 `*StatusLabel`、`styles.css` 的 `.status-*`，以及订单池、出库交付、收货录入、生产任务、对账收款的状态列。
   - PR 说明里贴完整映射表。拿不准归哪一级的，列出来问，不要自己猜。
3. 订单池、出库交付、收货录入、生产任务、对账收款、客户档案这 6 页的状态标签改用 `className={\`status-tag tone-${statusTone(text)}\`}`。
   - 旧的 `.status-中文` class 保留一个版本不删，避免漏掉的地方变成没颜色。
4. 每页列表上方右侧加一个小图例：「● 要处理 ● 待办 ● 进行中 ● 完成」，12px，可以收起。
5. 颜色以外再加形状区别，照顾色弱：阻塞用实心圆点，待办用空心圆点，其余不加。

**不改**：状态文字本身；状态由谁、何时改变。

**验收**：

- 新增 `scripts/check-status-tone.mjs`（纯 node，不开浏览器）：断言映射表覆盖上面 6 页出现的全部状态文字；同一文字只属于一级。加进 `test:checks` 的检查组（`scripts/check-group-manifest.mjs`）。
- 6 页截图。

### WP7 页面标题与空页面引导

**问题**（报告 #15、#36、#37）：20 页只有 2 页有 h1；5 个页面长期 0 条，看起来像没做完。

**具体怎么改**：

1. 每个页面的标题（现在显示在列表左上的页面名）改成 `<h1>`，视觉样式不变。
   - 一页只有一个 h1。
   - 收货录入、换模工单已有的 h1 保留。
2. 空页面的说明写清楚**为什么空**和**下一步做什么**，只用现有功能，不加新功能、不加假数据：
   - 卷料库存：「还没有入库的卷料。收货录入确认后，卷料会出现在这里。」+ 按钮「去收货录入」。
   - 覆膜袋：「还没有覆膜袋库存记录。」不加按钮。
   - 成品资料：「还没有成品资料。」不加按钮。
   - 员工机台：「还没有员工和机台资料。」不加按钮。
