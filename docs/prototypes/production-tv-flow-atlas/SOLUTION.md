# 生产电视大屏全流程评审原型

## 设计结论

电视大屏是公共、只读、远距查看的生产状态面，不是现场人员的操作终端。它只读取服务器已发布的排产与进度：制袋按机器展示当前任务和下一任务；总览中的丝印区只回答任务是否已印、什么时候印、由谁印，工人自主标记后的生产参数和完整队列留在丝印专页，不把办公室当天任务池伪装成办公室已分配的固定机台队列。

## 页面清单

1. 今日总览：三个制袋车间、九台制袋机和丝印进度的同屏摘要；每台制袋机明确显示当前任务是本机今日第几单。所有制袋后续队列共享同一个单行订单组件，固定为 `绝对序号 / 模拟客户人名 / 可选品名 / 尺寸规格 / 颜色组合 / 计划数量 / 业务类型 / 特殊要求`。无品名时不渲染品名也不保留空位；颜色组合使用明确的结构化业务字段，不从名称猜测；业务类型与特殊要求的文字标签统一放在末端，空间不足时只允许普通品名缩略。总览最多两单，车间详情与跨日顺序保留三单；三种页面都直接延续本机今日绝对编号，不重复显示“后续几单 / 已发布顺序”。丝印摘要仅保留任务、工人/机台编号、`已印 / 正在印 / 待印` 和计划或完成时间。

   品名使用可真实印在袋子上的模拟产品或品牌名称；补单、加急、返工等内部动作只作为状态或备注，不占用品名。同一演示订单在总览、车间详情、袋型图稿和丝印任务中保持同一品名与图稿身份。
2. 1号车间：制袋 1–3 号机的当前任务、订单袋型立体示意、颜色/图稿身份、小时级试算完成时间和后续三单。机器运行状态只在卡片标题栏显示一次，当前任务行不重复相同状态标签。后续三单使用与总览相同的单行字段顺序和末端标签，只提升字号与间距，并把预计时间保留为独立右侧列。袋型图例不重复显示 `订单袋型示意`/`图稿已确认`/`版本` 文案。当前订单明细固定为 `规格 / 袋身 / 提手 / 印刷` 四行键值列表，标签和值纵向对齐，不使用会形成 `2+1` 残缺行的二列事实网格。
3. 2号车间：制袋 4–6 号机沿用相同的四行当前订单明细、袋型立体示意、颜色/图稿身份、小时级试算完成时间和后续三单。袋型图例不重复显示 `订单袋型示意`/`图稿已确认`/`版本` 文案。
4. 3号车间：制袋 7–9 号机沿用相同的四行当前订单明细、袋型立体示意、颜色/图稿身份、小时级试算完成时间和后续三单。袋型图例不重复显示 `订单袋型示意`/`图稿已确认`/`版本` 文案。
5. 丝印任务池：采用与制袋车间一致的竖向分区。四个固定丝印工/机台各占一列，上方当前任务直接从订单身份开始，不再重复显示 `正在做 + 当前编号` 行，并在右侧显示复用制袋袋型模板的已审核定稿图；当前任务的文字信息只保留丝印直接需要的 `客户 + 品名 / 规格 / 袋身 / 印刷颜色与单双面`，不显示提手信息，定稿图只辅助识别，不能替代订单明细。下方显示本人已经认领的后续顺序，最右侧单独显示尚未被任何人认领的任务池。定稿图使用任务绑定的袋型、袋色、提手色、印刷色、印刷面和图稿版本，但图片下方不重复显示 `定稿图 / 图稿已确认 / 版本` 说明；版本仍保留在任务数据中，缺失、过期或未审核时仅显示 `待定稿`，不生成猜测图。颜色和统一文字编号（如 `印1-01`，表示印刷机 1 号机的第 01 号单）只用于后续已认领任务，未认领任务不预先生成个人编号。
6. 插单 / 顺序变更：办公室发布变更后自动刷新，并明确标出被移动的任务。
7. 异常暂停：显示机器、公开异常类型、影响和小时级重算结果，不显示维修或办公室私密备注。
8. 恢复生产：异常解除后回到当前任务并保留短时恢复提示。
9. 完工切换：本单完成，下一单自动成为当前任务。
10. 跨日继续：未完成任务置顶，显示昨日完成和当前剩余；完成后顺序复用统一单行订单组件，并延续本机今日绝对编号。
11. 首次载入：读取已发布排产时保持稳定骨架。
12. 数据中断：保留最后一次成功数据并显著标记停止更新时间。
13. 无已发布任务：全部设备保持待机，等待办公室发布排产。
14. 全系统标签语言：把电视原型中已验证的矩形语义标签提炼为业务类型、特殊要求、运行状态和人员/机台归属四层规范，并给出紧凑、标准、醒目三种密度，作为后续桌面、手机和大屏统一迁移的评审依据。

## 统一标签原则

- 业务类型回答“这是什么单”，特殊要求回答“生产要特别做什么”，运行状态回答“现在做到哪一步”，人员/机台归属回答“谁来做”；四种含义不能借用彼此的颜色。
- 红色只表示会阻断下一步的异常；`按扣`等非异常产品特征使用特征色，不使用危险红。
- 颜色始终与明确文字并存，人员颜色始终保留 `印1-01` 等编号；未知字段显示中性的 `待确认`，不猜测业务含义。
- 密集列表最多保留三枚优先标签，普通信息仍用文字；卡片只承载真实业务对象，不把所有字段都装进彩色标签。
- 本页只确认设计系统方向。生产页面在规范通过后再统一共享组件、语义变量和迁移顺序，不在评审阶段直接批量改造。

## 公开字段

- 机器 / 工作位
- 当前任务；总览最多两单、车间详情最多三单已发布后续队列及每单计划数量
- 客户或补货标记
- 产品名称
- 制袋及丝印专页中的尺寸、袋色、提手色/类型、印刷色/单双面；这些生产参数不进入总览丝印摘要
- 按订单字段和已批准图稿生成的袋型立体效果示意
- 袋身、提手比例和材质层直接复用 `/Users/xu/Documents/下单小程序/miniprogram/assets/templates` 与小程序 `bag-preview` 组件规则；30×38 业务规格按既有别名使用 30×37 竖款模板
- 计划数、已完成、剩余
- 小时级预计完成时间及试算/置信状态
- 丝印工/机台颜色与统一的 `印<机台号>-<当日两位顺序>` 非颜色文字编号、个人顺序
- 客户发货倒计时、发货时间和服务器反排的丝印最晚完成时间
- 插单、顺序变更、跨日继续、异常暂停等公开状态

## 明确不展示

完整客户备注、办公室内部备注、价格、成本、利润、对账、收款、审批操作和任何工作人员确认按钮。

## 评审数据

原型名称、订单与规格来自项目 `src/data/fixtures.js`。进度数字与屏幕时间用于方案演示，在外层评审画板和顶部状态中标记为演示数据，不代表实时生产事实。

演示订单数量仍遵循工厂的常规起订逻辑：通货/补货按至少一卷料展示，因尺寸不同通常约为 `2,000–3,000` 个；定制印刷和丝印任务按不少于 `1,000` 个展示。进度中的已完成、剩余数量可以低于起订量，但订单计划和后续任务不得使用不真实的百个级样例。
