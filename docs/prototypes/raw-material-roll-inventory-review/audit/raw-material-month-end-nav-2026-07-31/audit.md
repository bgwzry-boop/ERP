# 原材料—供应商月结导航审计

日期：2026-07-31

## 审计范围

检查 `原料管理 → 收货录入` 页面顶部的 `卷料库存 / 收货录入 / 供应商月结` 页签，以及点击 `供应商月结` 后左侧导航切换到 `财务管理` 的上下文变化。

## 用户目标

办公室人员在原材料日常工作中应清楚自己正在处理的是票据录入、逐卷库存，还是财务月结；页面切换不应让人误以为仍处于同一原材料局部工作台。

## 流程证据

1. `原料管理 → 收货录入`：左侧导航和页面任务一致。截图：`01-raw-material-receiving.png`。
2. 点击顶部 `供应商月结`：顶部仍以 `原材料工作台` 的局部页签呈现，但左侧激活项切换到 `财务管理 → 供应商月结`。截图：`02-supplier-month-end-finance-context.png`。

## 结论

当前安排存在信息架构冲突。`供应商月结` 放在财务管理本身是合理的；不合理的是它又作为原材料工作台的同级页签出现。局部页签应在同一父级上下文内切换，不能同时承担跨模块导航。

## 建议

- 原材料工作台顶部只保留 `卷料库存 / 收货录入`。
- `供应商月结` 只保留在左侧 `财务管理` 下，并继续按账号权限显示。
- 如办公室人员需要从原材料快速进入月结，在供应商或收货详情中提供明确的跨模块文字入口 `前往供应商月结 →`；不要再把它伪装成同级页签。
- 进入月结后，让左侧激活项、页面标题和面包屑共同明确 `财务管理 / 供应商月结`。
- 不合并两类业务对象：收货录入负责票据查重、OCR 复核和逐卷建档；供应商月结负责按供应商与账期匹配已确认卷料事实并形成应付依据。

## 可访问性风险

顶部控件使用 `tablist / tab` 语义，但其中一个操作改变了父级业务模块；这会让键盘和读屏用户误判其作用范围。当前证据不能确认焦点是否在切换后被正确移动或宣告，后续实现应补做键盘与读屏验证。
