# ERP 手机端全流程闭环方案

## 1. 方案目标

手机端不复制桌面 ERP。每个角色进入后只回答三件事：`现在做什么`、`做到哪一步`、`下一步点哪里`。所有页面沿用下单小程序的连续页面、克制卡片、16px 横向留白、44px 触控尺寸和固定主操作，并保留 ERP 的服务器权威校验、版本与审计边界。

当前高保真原型覆盖 9 个现场/经营岗位与 1 个账号设备平台附录，业务画板展示 90 个评审状态，宽度基线为 360 / 390 / 412px。底层仍保留 118 个状态页用于深链兼容、异常测试和同页状态复用，但导航页、提交确认、完成回执与异步就绪状态不再重复计入业务动线。当前仍是独立评审原型，生产业务页面尚未修改。

## 2. 界面与文字规则

- 不把“看不懂”归因于现场人员不熟 ERP；页面本身必须让当前任务、关键事实和下一步操作一眼成立。
- 视觉直接使用下单小程序的森林绿底板、苔藓绿主操作、浅绿工作面和连续白色详情面，不再使用通用蓝色后台卡片语言。
- 卡片只承载任务、证据、送货单、卷料、标签等真实业务对象；字段、核对项、决定说明和历史使用连续页面与分隔线。
- 标题说业务对象，按钮说要执行的动作；删除“系统将会”“正式页面中”“面向不熟 ERP”等不帮助当前操作的说明。
- `拍单 / 核对 / 打印 / 贴标` 的进度图标、页面标题和主操作保持一致；异常状态同时使用文字与语义色。
- PC 发布到手机的任务使用同一订单底稿；任务行固定按 `客户 + 货品 → 规格 + 颜色组合 → 类型 / 特殊要求 → 数量 + 机台或交接事实` 排列。

## 3. 统一链路结构

所有执行型任务复用同一状态骨架：

`待处理 → 查看事实/证据 → 执行或填写 → 提交核对 → 成功完成`

发生异常时进入独立闭环：

`发现异常 → 提交异常 → 等待有权角色处理 → 收到决定/新版本 → 恢复执行 → 完成`

每一次跨角色跳转都必须带回同一业务引用，正式实现至少保留：

- 业务对象 ID、任务 ID、源版本与当前版本；
- 当前状态、上一状态、状态变更时间和实际操作者；
- 原始证据、异常内容、决定内容与回执；
- 占用/版本冲突结果，禁止旧页面覆盖新决定；
- 写入幂等键与安全重试结果，禁止重复出库、重复标签和重复决定。

PC 的公共待办、订单录入、订单池、库存查询、出库交付、对账收款、客户档案、通用价格表、规格库存、员工机台、上线状态、设备验收、上线门禁、驱动诊断和打印作业不在手机端复制。手机只接收服务器已经发布、且当前岗位需要执行或确认的任务；登录时读取服务器确认的权限与上线结果，业务异常回到 PC 或决策岗处理后，再把同一订单的新版本和处理结果发回原手机任务。

## 4. 角色闭环

| 角色 | 主链路 | 已补齐的闭环 |
|---|---|---|
| 办公 A/B | 原料拍单、整单核对、可信打印、无序逐卷贴标 | 上传失败保留照片重传、打印失败安全补打、标签不符单卷隔离、9/9 收货完成 |
| 决策人 | 待决定、证据、确认、结果、历史 | 插单、出库差异、对账差异、抹零、采购建议、重大异常分别建链；首个有效决定生效 |
| 原材料经手人 | 扫卷、登记去向、确认发料 | 异常隔离、待处理、恢复扫描，不要求订单或生产任务 |
| 丝印工 | 接单、开工、报数、完成 | 当日产量与任务完成分开；异常上报后恢复 |
| 制袋工 | 接单、开工、报数、完成 | 当日产量与任务完成分开；设备异常可流转到维修 |
| 打包工 | 任务池、核货、逐包登记、完成 | 缺件/差异异常上报、等待真实结果、新版本到达后恢复 |
| 成品仓库 | 看到指令、备货、核纸单、实物出库 | 数量差异 → 办公接手 → 决策 → 新纸单版本 → 再核对 → 调整后出库 |
| 司机 | 核包装车、路线执行、送达凭证、完成 | 无人接货/地址异常 → 等待真实改约 → 原站继续配送 |
| 维修人员 | 报修、检查处置、恢复确认 | 等待配件/停机协调、条件到达后继续；巡检和保养完成后回任务池留短回执 |
| 平台附录：账号与设备 | 登录、首改密码、设备信任 | 登录失败、旧设备撤销、身份核验、绑定失败安全重试、审计结果；不计入生产岗位 |

## 5. 最关键的跨角色业务闭环

成品仓库的数量差异是本次完整性基准：

1. 仓库在当前纸单版本下发现实物数量不符并提交差异。
2. 办公 A/B 在共享待办中接手，核对出库指令、纸单版本、应出数与实物数。
3. 有权限的决策人查看证据后作出一次终局决定；旧版本客户端被阻止覆盖。
4. 决定回到办公室，办公室生成并可信打印新纸单版本。
5. 仓库收到决定回执，但在拿到新纸单前只能等待，不能完成实物出库。
6. 仓库核对新纸单、手机任务与实物一致后，提交调整后出库结果。

这条链同时验证了：角色权限分离、纸单版本门禁、跨角色回执、旧版本失效、恢复执行和最终落账前的二次核对。

## 6. 页面层级

- `当前任务`：默认只显示正在执行的一件事及一个主操作。
- `待处理`：同角色任务队列，显示数量、优先级和阻塞状态。
- `全部功能`：仅作为可点击原型中的工具入口保留，不出现在业务流程画板，也不参与岗位动线计数。
- `提交确认 / 完成回执 / 处理结果`：优先收在当前业务对象页面的确认层、弹窗或状态更新中；只有切换业务对象、责任人或不可逆安全门禁时才新开页面。
- 二级信息：历史、审计、OCR 原文、设备细节和权限说明按需展开，不占用正常作业首屏。

## 7. 进入生产实现前的门禁

1. 先由业务人员在原型中走通仓库差异、原料 9/9 完成、决策回执、维修阻塞和换机五条基准链。
2. 明确每条写入对应的服务端命令、版本号、幂等键和审计字段。
3. 用真实 Android 手机验证 360 / 390 / 412px、拍照、蓝牙打印结果、失败重试和重复防护。
4. 只有原型获得明确批准后，才进入生产业务页面实施。
