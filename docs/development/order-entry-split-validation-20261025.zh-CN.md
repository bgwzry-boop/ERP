# 订单录入拆单接入与验证记录

日期：2026-10-25。目标是恢复负责人接受的两层拆单体验，并保留当前正式报价、授权本单价、小程序锁价、补单确认和原请求重试。本轮为独立分支本地整改，未部署、未移动canonical、未修改真实业务数据。

## 基线与范围

- 开工主目录版本检查21/21通过，fetch后从 `origin/codex/staging-current` 的 `080863ebc62b1a32ff989d54eb1b427548511894` 建立 `codex/order-entry-split-20261025` 工作树。
- 当前完整电脑入口恢复每行的“拆分明细行”，复用原先对半拆分并保持合计的逻辑；数量少于2、非整数、取消明细、留货绑定及小程序锁价继续受限。
- 页尾接回“按客户/交付拆单”，通过原后台生成分组及计划摘要，使用可访问的最终确认对话框；返回或Esc不下单，关闭后焦点返回入口。
- 拆行使旧报价失效，并清除被拆原行的授权改价，避免一次性费用被静默复制。其他未拆行的输入保留；操作提示明确要求重新核价。
- 拆单提交补齐正式报价编号、关联原单确认清单和固定幂等标识。预览金额以当前正式报价行计算，不把旧预估金额当正式报价。
- 拆单不确定回执继承已有冻结和导航阻断，保留计划、报价和请求体按原内容重试。明确拒绝可返回修正，已不确定请求后续即使409也不释放原请求。
- 当前默认草稿不因队列刷新移除已确认项而切换成另一份草稿，保留成功回执并避免再次提交。
