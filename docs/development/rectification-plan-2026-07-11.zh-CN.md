## 一、当前结论

当前系统是高完成度 ERP 原型和 V1 候选实现，但还不能宣布生产上线完成。

| 指标 | 当前值 | 说明 |
| --- | --- | --- |
| P0 可演示原型 | 约 `97-98%` | 办公室主流程、API 边界和大部分异常入口已具备。 |
| V1 真实上线就绪 | 约 `80-83%` | 生产事实源、真实基础设施、设备和现场验收仍未闭环。 |
| 发布门禁 | `0/4` | 未达到正式发布条件。 |
| 现场证据 | `0/34` | 自动化报告不能代替现场证据。 |
| 负责人签字 | `0/6` | 办公室、库房、车间、司机、财务、管理尚未签收。 |

已完成批次 A，以及批次 B 的 B1-B2：

- `demo/test/production` 运行模式和权限隔离已建立。
- production 强制严格认证、PostgreSQL、对象存储和 `Idempotency-Key`。
- 订单、库存、交付、对账、原材料、打印和司机核心写链已有首轮事务、幂等和并发保护。
- 本地自动化和 PostgreSQL 16 容器集成已经通过。

批次 B3 / R1.1-R1.5 已完成代码和 PostgreSQL 16 容器验收：订单草稿、明细、待办和日志已落 PostgreSQL；正式订单、草稿状态、库存占用、库存流水和操作日志已合并为单一确认事务；核心启动快照覆盖客户、订单、库存、交付、对账、生产、打包和日志等 26 个集合。production 空库不再显示 seed，API 重启后草稿可续编，双会话旧版本只有一个成功。

当前 production profile 为 31 个 PostgreSQL 仓储默认项、2 个对象存储和 33 个持久化对象。PostgreSQL live 还覆盖旧草稿确认整单回滚、稀疏订单 / 交付编号不碰撞、两个不同草稿并发使用同一业务 ID 时只有一个成功且另一单 `409` 回滚、数据库提交版本投影和已持久化对账明细金额保持。`npm test`、批次 B、PostgreSQL 16 live、production profile live、OpenAPI 和差异检查均通过。下一阶段进入 R2 真实基础设施和可恢复部署；本地容器通过仍不等于真实生产环境已验收。

批次 C 附件与财务可信的代码检查点已完成：附件按业务对象、用途和 SHA-256 摘要去重，内容寻址写入文件存储，生产幂等重放 / 冲突和并发同摘要收敛已在 PostgreSQL 16 验证；历史重复元数据保留但业务列表只显示规范附件；附件创建 / 复用均写操作日志。对账页已拆分本期应收、本期实收、本期未收、历史欠款和累计欠款，并在 `1280x720`、`390x844` 验证无横向溢出。真实对象存储和财务现场核对仍属于 R2 / R4，不能由本地验证替代。

## 二、整改目标

1. production 的业务事实只来自 PostgreSQL 和对象存储。
2. 核心写链具备幂等、并发冲突、事务回滚和数据库提交版本回读。
3. API 重启、浏览器刷新和双会话操作后数据保持一致。
4. 六个办公室核心页面形成统一、高密度、可扫描的 ERP 工作台。
5. 大型组合文件按领域拆分，业务规则只有一个实现位置。
6. 真实打印、司机手机和业务试跑通过现场验收。
7. 发布门禁、现场证据和负责人签字全部完成后才宣布 V1 完成。

## 九、上线红线

以下任一项存在时，不得宣布 V1 完成：

- production 仍可把 seed、内存、JSON 或本地文件当正式事实源。
- 正式环境仍可使用 seed 账号、身份 Header 或前端本地写入回退。

- PostgreSQL、对象存储、备份恢复、远端恢复或回滚演练未完成。
- 现场证据、负责人签字或 V1/V2 边界未确认。
- 真实密钥、连接串、bucket、token、命令或本机路径进入 Git 和普通报告。
