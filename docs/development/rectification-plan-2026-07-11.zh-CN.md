# ERP 系统代码与 UI 整改方案

制定日期：2026-07-11
版本：V6
适用范围：V1 上线收口、代码精简、UI 统一和现场验收

执行口径：本方案按“代码质量整改”和“真实上线验收”双轨推进。代码、自动化和本地预览通过，不等于真实生产环境、打印机、司机手机和现场业务已经验收。

## 一、整改结论

当前系统不是未开发原型，也不是已经完成的生产系统。准确状态如下：

| 维度 | 当前判断 | 说明 |
| --- | --- | --- |
| P0 原型 / 代码能力 | `97-98%` | 六个办公室主页面、角色工具、核心 API、权限和主要事务链已经具备。 |
| V1 上线就绪 | `80-83%` | 真实基础设施、硬件、业务试跑、证据和签字未闭环。 |
| 发布门禁 | `0/4` | 当前不能宣布 V1 完成或正式上线。 |
| 现场证据 | `0/34` | 自动化报告不能替代真实出纸、扫码、定位和业务样本。 |
| 负责人签字 | `0/6` | 办公室、仓库、车间、司机、财务、管理尚未签收。 |

已完成的关键基础：

- `demo / test / production` 运行模式、严格认证和权限隔离。
- production 的 PostgreSQL、对象存储、幂等键和禁止本地业务写入回退边界。
- 订单确认、库存占用、交付、收款核销、原材料、打印和司机主写链的首轮事务与并发保护。
- 六个办公室核心页面和生产、原材料、车间、司机、上线状态等角色页面的 feature 归属拆分。
- 公共待办、订单池、库存、交付、司机、原材料和供应商月结读取编排已从 `App.jsx` 迁出。
- 全量测试、生产构建和本地 PostgreSQL 16 验证已形成自动化基线。

仍未完成的关键事项：

- 真实 PostgreSQL、专用恢复验证库、真实对象存储和受控 Git 远端。
- Windows 打印主机、针式打印机、标签打印机、纸张对位和真实扫码。
- 司机真实手机的登录、相机、定位、导航、水印和弱网测试。
- 脱敏真实订单全链路试跑、现场证据、负责人签字和灰度上线。
- `App.jsx`、`apiServer.mjs`、`styles.css` 和 V1 状态相关文件仍显著过大。

## 二、整改原则

1. **先保业务，再拆结构**：每轮只移动一个领域的职责，不同时修改业务状态机。
2. **服务端事实优先**：production 不得用 seed、内存、JSON、本地文件或浏览器投影代替正式事实源。
3. **先建立共享骨架，再逐页改 UI**：避免六个页面分别产生新的重复样式。
4. **真实验收单独计数**：本地测试通过不增加现场证据、签字和发布门禁数字。
5. **小批次可回退**：每轮必须可独立测试、独立提交、独立回退。
6. **不扩展 V2**：售后绩效、工资考勤、企业微信自动化、高级 BI 和路线优化不进入本轮。

## 三、问题清单与优先级

### P0：上线阻断

| 编号 | 问题 | 风险 | 整改结果要求 |
| --- | --- | --- | --- |
| P0-01 | 真实生产 PostgreSQL 未验收 | 本地容器不能证明生产数据可持续运行 | 迁移、权限、并发、重启和 runtime smoke 全部通过。 |
| P0-02 | 备份恢复和远端恢复未验收 | 数据库或主机故障后恢复能力未知 | 专用验证库恢复成功，另一受控目录 / 主机按完整 commit 恢复成功。 |
| P0-03 | 真实对象存储未验收 | 附件和对账文件可能无法恢复或安全访问 | 写入、读回、签名 URL、删除、版本、生命周期和加密检查通过。 |
| P0-04 | 打印与司机真机未验收 | 预览成功不能证明出纸、扫码、定位成功 | 样张、扫码、spool 回写、相机、定位、导航和弱网证据齐全。 |
| P0-05 | 真实业务试跑未完成 | 规则和现场操作仍可能不匹配 | 主流程和异常流程用脱敏真实样本跑通。 |
| P0-06 | 证据、签字和门禁未完成 | 无法形成上线责任闭环 | 门禁 `4/4`、证据 `34/34`、签字 `6/6`。 |

### P1：代码质量与 UI

| 编号 | 问题 | 当前证据 | 整改目标 |
| --- | --- | --- | --- |
| P1-01 | 应用组合根过大 | `src/App.jsx` 约 `9,747` 行 | 仅保留会话、导航、路由、全局反馈和领域装配，目标约 `1,500` 行以内。 |
| P1-02 | API 主入口过大 | `server/apiServer.mjs` 约 `22,758` 行 | 仅保留启动、中间件、依赖注入和路由装配，业务进入 service / domain。 |
| P1-03 | CSS 集中且重复 | `src/styles.css` 约 `8,943` 行 | 拆为 tokens、shell、table、form、panel、mobile 和领域样式。 |
| P1-04 | V1 状态模块过大 | 页面约 `5,958` 行，client 约 `5,519` 行 | 按阶段卡、数据 normalizer 和 action client 分组，减少单文件职责。 |
| P1-05 | 页面 UI 模式不完全一致 | 标题、筛选、表格、详情和状态反馈存在差异 | 六个主页面统一骨架、密度、状态和响应式行为。 |
| P1-06 | 读取 / 写入编排仍混在 App | D10-D12 已迁出核心、角色工具和生产任务读取 | 继续按打印、主数据、对账、V1 状态及写动作逐域迁出。 |

### P2：暂缓项

- 售后责任分摊、绩效扣款和完整售后中心。
- 工资、考勤和完整人事。
- 企业微信自动通知和客户群自动发送。
- 高级 BI、自动排产、路线优化和深度毛利分析。

## 四、执行路线

整改分成 A、B、C 三条轨道。A 是生产上线主线；B、C 可以并行，但不能替代 A 的验收。

### A 轨：生产上线收口

#### A1 真实基础设施

1. 填写安全 production env，保持未跟踪、`0600` 和报告脱敏。
2. 连接真实 PostgreSQL，执行迁移计划、checksum、权限和重复执行检查。
3. 在专用可重置恢复验证库执行备份 / 恢复抽样，禁止重置生产库。
4. 连接真实 OSS / S3 / COS，执行附件与对账导出的读写和治理检查。
5. 配置受控 Git 远端，完成全新目录 clone、安装、构建、迁移计划和启动恢复。

退出条件：生产持久化证据、runtime smoke 和第一阶段 closeout 全部通过。

#### A2 真实设备

1. 配置 Windows 11 打印主机、驱动、端口、队列、纸张和页边距。
2. 验证单据、快递 / 快运标签和原材料防水标签的真实出纸、对位、扫码、作废重打和状态回读。
3. 在司机真实手机验证登录、扫码、相机、定位、导航、水印、弱网和送达证据。

退出条件：打印 closeout 和司机真机 closeout 均为 ready，并保留脱敏证据。

#### A3 真实业务试跑

必须覆盖：

- 现货、缺货、定制印刷和外协订单。
- `白印黑`、`白袋黑提`、`黄袋红提`、单双面和其他备注。
- 库存占用、释放、改量、作废、补货、生产、报工和打包。
- 自提、送货、快递快运、数量不符和无法出库。
- 对账、发送、收款、差额、核销、附件和 Excel 导出。
- 原材料送货单、复核、一卷一标、扫码、领料、余料和供应商月结。

退出条件：办公室、仓库、车间、司机和财务分别完成主流程及异常流程验收。

#### A4 发布收口

1. 回填现场证据 `34/34`。
2. 完成负责人签字 `6/6`。
3. 重新生成 release candidate、go-live suite 和 handoff pack。
4. 发布门禁达到 `4/4` 后安排灰度上线。

### B 轨：代码结构整改

#### B1 前端编排拆分

建议按以下轮次执行：

| 轮次 | 范围 | 不允许改变 | 验收重点 |
| --- | --- | --- | --- |
| B1.1（已通过） | 生产任务、打包任务、机台队列读取 | 报工、排产、打包完成规则 | 三路读取成功 / 失败 / production 降级。 |
| B1.2 | 打印配置、作业池、设备状态读取 | 打印权限、spool 和驱动合同 | 队列合并、状态轮询、无设备状态。 |
| B1.3 | 主数据、库存明细、对账和 V1 状态读取 | 审核、导入、核销和上线权限 | 分页、空态、权限拒绝和快照新鲜度。 |
| B1.4 | 订单、库存、交付、生产、打印写动作 | API URL、payload、幂等和事务边界 | 成功刷新、409 冲突、权限拒绝和网络失败。 |
| B1.5 | App 壳层收口 | 登录、导航、路由和反馈行为 | `App.jsx` 只保留应用装配。 |

每个读取 / 写入模块采用可注入 action factory + React hook，直接测试业务结果和反馈，不依赖完整页面渲染。

#### B2 API 业务实现拆分

现有 routes 只完成了多数 HTTP 分发，下一步按领域迁移业务实现：

1. 订单与库存。
2. 出库交付与打印。
3. 对账收款与附件。
4. 生产打包与原材料。
5. 司机与主数据。
6. V1 上线状态与执行器。

每个领域形成 `route -> service -> repository`：

- route：解析请求、认证、权限、HTTP 状态和响应。
- service：业务规则、事务编排、幂等和冲突映射。
- repository：参数化 SQL、锁、提交版本和持久化投影。

退出条件：`apiServer.mjs` 不再包含领域业务实现；专项测试和 PostgreSQL live 检查通过。

#### B3 CSS 与共享组件分层

建议结构：

```text
src/styles/
  tokens.css
  shell.css
  table.css
  form.css
  panel.css
  states.css
  mobile.css
  features/*.css
```

优先建立并复用：`PageHead`、`FilterBar`、`DenseTable`、`StatusTag`、`DetailsPanel`、`EmptyState`、`ErrorState`、`LoadingState`、`PermissionState`。

退出条件：删除重复选择器前有 `rg` 调用证明；页面无视觉回归；`styles.css` 降为兼容入口或删除。

### C 轨：UI 重构

#### C1 统一设计基线

- 窄左侧导航 + 顶部页面标题 / 动作栏。
- 六个办公室核心页面优先，角色工具按权限进入二级分组。
- 高密度 SaaS ERP 视觉，不使用营销式大卡片、大留白和装饰性渐变。
- 库存状态固定为：可用绿、占用黄、缺货红、待处理灰。
- 公共状态固定为：正常蓝 / 绿、待处理黄、异常红、完成弱绿、作废灰。
- 图标按钮使用现有图标库并提供 tooltip；二元设置使用开关或复选框。
- 桌面显示紧凑表格；手机端显示可操作摘要和详情，不强压完整表格。

#### C2 页面整改顺序

1. **公共待办**：突出异常、紧急度、批量处理和来源定位。
2. **订单录入**：保留大文本识别区、行内编辑和复杂印刷侧栏；定制印刷不得显示成普通空白袋。
3. **订单池**：统一筛选、状态、详情、修改资格和跨模块定位。
4. **库存查询**：突出可用、占用、缺货、待处理、来源和流水。
5. **出库交付**：突出今日、异常、待打印、待拉走和下一步动作；货品摘要使用工厂短写。
6. **对账收款**：保持左侧客户、右侧账期订单和收款状态，五项金额口径不混合。
7. **角色工具**：生产 / 打包、原材料、车间、司机和上线状态按相同骨架收口。

#### C3 视觉验收

固定视口：`1280x720`、`1440x900`、`1920x1080`、`390x844`。

每页必须通过：

- 页面和关键容器无横向溢出。
- 文本、按钮、表格、侧栏和弹窗无重叠。
- 加载、空、错误、无权限和过期快照状态齐全。
- 页面主要动作可完成，控制台错误 / 警告为 0。
- 定制印刷摘要、中文业务标签和机器计数“不入库”文案保持正确。

## 六、验收与质量门禁

每个代码轮次至少执行对应专项，并在轮次结束执行：

```bash
npm run lint
npm run build
npm test
git diff --check
```

涉及数据库事务时追加：

```bash
npm run batch-b:check
npm run db:postgres-live:check
```

涉及 UI 时追加浏览器桌面 / 手机验证、控制台检查和横向溢出检查。

真实环境、打印机或手机未实际执行时，交付结论必须写“未验证”，不得用模拟结果代替。

## 七、每轮交付格式

每轮完成后固定汇报：

1. 本轮修改了什么。
2. 解决了什么问题。
3. 还有什么问题没有修改。
4. 执行了哪些验证，结果如何。
5. 门禁、证据和签字数字是否变化。
6. 下一轮建议、风险和所需配合。

## 八、推荐执行顺序

当前推荐同时推进两项：

1. **技术运维主线**：立即执行 A1，补真实 PostgreSQL、恢复验证库、对象存储和受控 Git 远端。
2. **代码整改主线**：B1.1 已通过，下一轮执行 B1.2，迁出打印配置、打印作业池和设备状态读取，再处理其他工作区编排。
3. **UI 主线**：B3 共享骨架形成后，从公共待办和订单录入开始逐页重构；每页单独验收，不进行一次性全站换肤。
4. **设备与业务主线**：A1 通过后进入 A2，随后执行 A3 和 A4。

这样可以继续降低代码风险并改善 UI，同时不掩盖真实上线阻塞。

## 九、上线红线

以下任一项存在时，不得宣布 V1 完成：

- production 仍可把 seed、内存、JSON 或本地文件当正式事实源。
- 正式环境仍可使用 seed 账号、身份 Header 或浏览器本地业务写入回退。
- 重复请求可能重复扣库存、收款、核销、打印或派送。
- 打印只有预览，没有真实出纸、扫码和状态回读。
- 司机端只有浏览器模拟，没有真实手机权限和现场证据。
- PostgreSQL、对象存储、备份恢复、远端恢复或回滚演练未完成。
- 现场证据、负责人签字或 V1 / V2 边界未确认。
- 真实密钥、连接串、bucket、token、命令或本机路径进入 Git 和普通报告。
