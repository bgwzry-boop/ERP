# 人意拍单：退货方向与票面颜色修复

日期：2026-10-30。开发基线为 `711a5c69d440d5003bdd02fed4e1e88b0da37f7e`；本记录描述独立开发分支，不是发布证明。提交 PR 后由统一发布任务审核、测试并按受控流程发布；本任务不合并、不部署、不推进唯一基线。

## 业务结论

负责人已实测高拍仪能够调用、拍照，腾讯 OCR 可以识别。两张人意测试单的原照片均已保存为原始审计附件并关联入库草稿；关联原单的附件不按未关联临时文件清理。本轮读取原图并校验文件摘要；网页拍摄保存的是高拍仪视频帧生成的 JPEG，不声称是设备 RAW 文件。

2026-10-30 负责人确认：未建立厂家与厂内颜色对应关系时，先用票面名称。以后汇总同一厂家的颜色，由工作人员手写备注实际对应的厂内颜色，再由有权限人员维护对应关系。该决定替代此前“未映射就阻断入库”的要求。

- 厂家票面颜色保留，厂内标准色可以留空；不把海兰、米黄、梅红擅自换成相似标准色。
- 每卷记录暂用票面色的来源状态，核对、卷标、贴标与库存展示使用该卷颜色。颜色未识别、规格或数量缺失、价格及整单金额不一致等原有检查继续有效。
- 厂家票面名称不自动视为订单的厂内标准色，不据此作出“库存足够”的自动判断；实际库存仍可查询、扫码领料。
- 后续维护映射须有权限及审计。当前未复核草稿可回填同厂家同票面颜色；不自动回写已经入库的历史记录。专门的可打印厂家颜色盘点表与手写备注归档入口属于后续工作，本次未新增。

## 问题与修改

1. 退货票选成收货时，显式选项将负数明细解析为正数；原检测又漏掉拆行的“退带色布”。现在从保存的 OCR 表格及原始明细检测强退货证据，服务端拒绝按收货复核，电脑和手机提供明确的“改为退货单核对”。该操作沿用带版本校验、有审计的重解析，不重调腾讯 OCR，不静默切换。
2. 退货方向更正后保持负数重量、负数金额，没有入库卷料，不要求虚构入库颜色或规格。实际退货的类别、价格等原有核对要求保留。
3. 无映射的票面颜色不再泛称“颜色待补”，显示“暂用票面色 / 厂内色待统一”。修正桌面逐卷颜色从单据首行回填的错误，并补齐贴标、库存和领料查询的逐卷颜色优先级。
4. 桌面已接回现有的厂家颜色维护弹窗，保存后只回填对应颜色；打开弹窗时关闭旧行编辑器，避免旧空值覆盖新规则。
5. 修正桌面退货选择被内部收货筛选覆盖、手机更正后退出核对页，以及操作提示误显示程序函数文字的问题。保留账号/权限/页面切换时丢弃过期回执的保护。
