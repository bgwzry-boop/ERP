# 2026-11-18 构建依赖替换评审

## 范围与授权

负责人明确同意评审并替换有漏洞的构建依赖，要求保留业务规则、原测试断言和安全检查，全部通过后仅发布 staging。此文记录候选验证，不是已部署证明。生产不在授权范围。

## 根因与替换

- GHSA-fc5q-39xc-vjpf：Picomatch 的单分支重复扩展通配符会生成指数回溯正则。核对时最新 4.0.7 仍受影响，公告无已发布修复版。
- 旧 Rollup 分发物还内嵌了匹配器；只覆盖外部包或回退 Vite 不能证明问题消除。
- 采用官方 Vite **8.3.8**、React 插件 **6.3.0**、Rolldown，移除旧 Rollup 构建链。原配置、正式页面及桌面/手机入口不改。测试直接使用的 esbuild 显式列为 **0.28.2**，满足 Vite 新版的 peer 范围，不借助 force/legacy-peer-deps。
- 本地私有构建包 `@bagwin/build-glob` 的匹配实际调用固定 **Minimatch 11.0.9** 非回溯引擎，不生成 glob 正则。npm override 指向真实替代实现，不伪造 Picomatch 修复版本。
- 只复用 Picomatch 4.0.4 的词法扫描器，保留 MIT 许可、上游文件 SHA-256 和精确来源；旧 parse/正则执行引擎不在包中。各项目使用 `install-links=true`，通过锁文件安装真实副本，回归比较安装副本与审查源码摘要。

## 保留与边界

- 原全部业务检查/断言、安全审计级别、资源大小预算及数据库迁移不变。
- 文件 glob 的尾部 `/**` 包含父项语义显式兼容；保留忽略/否定规则，避免 Tinyglobby 的 expandDirectories 漏掉文件。范围展开达到边界时显式拒绝，不接受依赖静默截断。
- 支持实际使用的匹配谓词、词法 scan、dot/nocase/ignore/negation/basename、Windows 分隔符及既有普通模式。
- 不假装完整仿真旧库：正则序列化、raw regex、capture、跨目录 Bash 星号和 substring 等 API 明确失败。当前 ERP 配置不使用它们；以后增加字符串 `assetsInclude` 等依赖 makeRe 的配置须重新评审，禁止静默回退旧引擎。
- 匹配器只在构建/开发工具链使用，不进入 API 业务决策，不修改 OCR、价格、工资、库存或认证规则。

## 验证设计

`npm run build-toolchain:check` 加到 CI 独立步骤，原测试分组不删减：

1. 975 个既有普通路径匹配结果快照，以及 scan 输出兼容。
2. 原漏洞 `+(*a)` 在旧依赖的隔离 worker 中超过 500ms 被终止；替代实现对同型长输入及多种重复模式在有硬性超时的 worker 中返回正确结果。不是只检查版本名。
3. 模式/输入/数组/展开边界及不支持的 API 必须明确失败，防止静默误匹配。
4. Tinyglobby/Fdir 实际临时文件遍历，包含括号/方括号文件、JS/JSX 和测试文件忽略。
5. 真实 Vite 临时服务器：合法 JS 可读，环境文件（含 raw 和绝对路径）、npm 配置、证书和 Git 配置均 403，不泄露合成秘密。真实目录路径先规范化，不放松服务目录限制。
6. 根项目和四个原型的真实安装源/引擎核对；确认不能解析到旧 Rollup。原根/完整评审构建、82 项单元与完整页面/业务回归继续运行。

所有审计必须成功返回且漏洞为零；网络失败不是通过。候选首次复查遇到过审计网络错误、过期本地副本、目录匹配语义差异和临时目录符号路径问题，分别重跑/修复后保留严格断言。已完成的局部验证不替代最终 exact-commit 云端 CI、截图、受控锁和公网验收。
