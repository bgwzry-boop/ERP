# ERP 代码、上线与 UI 整改执行方案

制定日期：2026-07-12
当前版本：V8.39
适用范围：V1 小范围真实上线、代码治理、UI 重构和现场验收

## 一、执行结论

当前系统的核心业务代码已经基本具备，但不能判定为“全部完成”或“可以直接正式上线”。

| 维度 | 当前估算 | 判断 |
| --- | ---: | --- |
| 需求确认 | `85-90%` | V1 主流程已明确，少量现场口径仍需真实试跑确认。 |
| P0 原型 / 代码能力 | `97-98%` | 六个办公室主页面、角色工具、核心 API、权限、事务和主要闭环已具备。 |
| V1 上线就绪 | `80-83%` | 真实员工、生产环境、设备、业务试跑和责任签收未闭环。 |
| 发布门禁 | `0/4` | 当前禁止宣布正式完成或正式上线。 |
| 现场证据 | `0/34` | 自动化报告不能替代真实出纸、扫码、定位和业务样本。 |
| 负责人签字 | `0/6` | 办公室、仓库、车间、司机、财务、管理均未完成签收。 |

结论分为两部分：

1. **代码不是空原型**：订单、库存、出库、生产、原材料、打印、司机和财务均有可运行主链，并有权限、幂等、事务和 E2E 基线。
2. **上线尚未完成**：真实生产资源、真实硬件、真实业务数据、现场证据和负责人签字仍是硬阻塞，继续拆代码或美化 UI 不能替代这些验收。

## 四、整改路线

整改分为 A、B、C 三轨。A 是上线主线，B 和 C 可并行，但不得占用真实环境和现场验收所需资源。

### A 轨：生产上线收口

| 阶段 | 任务 | 主要输入 | 退出条件 |
| --- | --- | --- | --- |
| A1 身份与环境 | 导入真实员工，完成首次改密和机器绑定；填写安全 production env。 | 员工清单、岗位、账号、机台、数据库和对象存储真实值。 | 8 岗位账号 ready；env intake / preflight 无阻塞。 |
| A2 持久化与部署 | 执行真实 PostgreSQL 迁移、备份恢复、对象存储治理、长驻 API、TLS、日志和健康检查。 | 真实服务器、恢复验证库、对象存储、受控 Git 远端。 | 第一阶段 persistence evidence、runtime smoke 和 closeout ready。 |
| A3 真实设备 | 配置打印主机、针式 / 标签打印机、纸张；验证司机真实手机。 | Windows 11、打印机、标签纸、真实手机和网络。 | 打印 closeout、司机 closeout ready。 |
| A4 业务试跑 | 按岗位跑现货、缺货、定制、外协、出库、对账、原材料和异常流程。 | 脱敏真实订单、库存、客户、供应商和异常样本。 | 办公室、仓库、车间、司机、财务主流程及异常流程签收。 |
| A5 发布放行 | 刷新 release candidate、suite 和 handoff，完成签字与边界确认。 | 全部现场证据和负责人决定。 | `34/34`、`6/6`、`4/4`，再安排小范围灰度。 |

### B 轨：代码精简与安全

建议按小批次执行，每轮只迁一个责任边界：

1. **B6.1 生产状态投影（已完成）**：V8.28 已完成提取、脱敏、API 合同和浏览器回归。
2. **B6.2 发布 / 负责人摘要投影（已完成）**：V8.29 已迁出完成度、发布候选、负责人决策、模块和顶层阻塞投影。
3. **B6.3 角色任务与 V1/V2 边界（已完成）**：V8.30 已迁出 unblock plan、role task board 和 boundary brief。
4. **B6.4 完成审计与现场验收投影（已完成）**：V8.31 已迁出 completion audit、runtime blockers 和 field acceptance，并关闭上游 ready 绕过七项审计的风险。
5. **B6.5 App 页面控制器（八轮已完成）**：V8.32 已迁 V1 actions，V8.33 已迁原材料，V8.34 已迁司机动作，V8.35 已迁对账动作，V8.36 已迁基础资料动作，V8.37 已迁公共待办动作，V8.38 已迁出库交付编排，V8.39 已迁库存修正、详情 / 队列 / 流水刷新和跨模块来源定位；正式模式统一阻断非 API 来源。下一轮审计订单录入 / 订单池剩余回调。禁止复制权限表和 API URL。
6. **B6.6 V1 大服务二次拆分**：按 evidence progress、quality、signoff 和 production env 子域拆分。
7. **B6.7 CSS 清理**：通过选择器调用扫描和截图回归，逐 feature 删除旧重复规则。

每轮代码整改必须同时满足：

- production 网络失败、权限拒绝、冲突或持久化失败时 fail-closed。
- 操作人只取认证会话，浏览器字段不能伪造身份。
- 事务、revision、幂等键、状态机和错误码不因重构改变。
- 敏感值、路径、连接串和命令参数不得进入响应、日志、报告或 Git。
- 新 service 有直接测试，route / HTTP 合同和 PostgreSQL live 有对应回归。

### C 轨：UI 渐进重构

UI 不推翻已完成页面，采用运营工作台式渐进收敛。

#### 统一基线

- 窄左侧导航 + 顶部页面标题 / 动作栏。
- 高密度 SaaS ERP，不做大卡片、大留白、营销式首页或嵌套卡片。
- 六个 P0 页面优先：公共待办、订单录入、订单池、库存查询、出库交付、对账收款。
- 角色工具放在权限可见的二级导航；内部英文枚举不得进入可见表格。
- 统一 loading、empty、error、permission denied、stale、conflict 和 success 状态。
- 状态颜色保持：正常蓝 / 绿、待处理黄、异常红、完成柔和绿、作废灰。

#### 页面顺序

1. 壳层、导航、顶部动作、通知和全局反馈。
2. 订单录入、订单池、库存和出库交付。
3. 公共待办、对账收款。
4. 生产 / 打包、原材料、车间和司机。
5. 基础资料和 V1 上线状态。

#### 业务显示红线

- 定制印刷可见款式显示 `定制印刷`，基础袋款仅用于库存 / 生产匹配。
- 货品摘要为“品名 + 尺寸 + 紧凑颜色 + 单双面 + 数量 + 备注”。
- 支持 `白印黑`、`白袋黑提`、`黄袋红提`；两类颜色同时存在时显示 `白印黑 / 白袋黑提`。
- 机器计数只能显示为动作 / 周期计数，不得显示为合格产量、库存或计费数量。
- 关键动作在 `1024x768` 和 `390x844` 首屏或合理工作区内可达，长文本不得覆盖控件。
