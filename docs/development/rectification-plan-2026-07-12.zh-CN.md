## 一、执行结论

当前系统的核心业务代码已经基本具备，但不能判定为“全部完成”或“可以直接正式上线”。

| 维度 | 当前估算 | 判断 |
| --- | ---: | --- |
| 需求确认 | `85-90%` | V1 主流程已明确，少量现场口径仍需真实试跑确认。 |
| P0 原型 / 代码能力 | `97-98%` | 六个办公室主页面、角色工具、核心 API、权限、事务和主要闭环已具备。 |
| V1 上线就绪 | `80-83%` | 真实员工、生产环境、设备、业务试跑和责任签收未闭环。 |
| 发布门禁 | `0/4` | 当前禁止宣布正式完成或正式上线。 |
| 现场证据 | `0/34` | 自动化报告不能替代真实出纸、扫码、定位和业务样本。 |
| 负责人签字 | `0/6` | 办公室、仓库、车间、司机、财务、管理均未完成签收。 |

结论分为两部分：

1. **代码不是空原型**：订单、库存、出库、生产、原材料、打印、司机和财务均有可运行主链，并有权限、幂等、事务和 E2E 基线。
2. **上线尚未完成**：真实生产资源、真实硬件、真实业务数据、现场证据和负责人签字仍是硬阻塞，继续拆代码或美化 UI 不能替代这些验收。

### C 轨：UI 渐进重构

UI 不推翻已完成页面，采用运营工作台式渐进收敛。

#### 统一基线

- 窄左侧导航 + 顶部页面标题 / 动作栏。
- 高密度 SaaS ERP，不做大卡片、大留白、营销式首页或嵌套卡片。
- 六个 P0 页面优先：公共待办、订单录入、订单池、库存查询、出库交付、对账收款。
- 角色工具放在权限可见的二级导航；内部英文枚举不得进入可见表格。
- 统一 loading、empty、error、permission denied、stale、conflict 和 success 状态。
- 状态颜色保持：正常蓝 / 绿、待处理黄、异常红、完成柔和绿、作废灰。

#### 页面顺序

1. 壳层、导航、顶部动作、通知和全局反馈。
2. 订单录入、订单池、库存和出库交付。
3. 公共待办、对账收款。
4. 生产 / 打包、原材料、车间和司机。
5. 基础资料和 V1 上线状态。

#### 业务显示红线

- 定制印刷可见款式显示 `定制印刷`，基础袋款仅用于库存 / 生产匹配。
- 货品摘要为“品名 + 尺寸 + 紧凑颜色 + 单双面 + 数量 + 备注”。
- 支持 `白印黑`、`白袋黑提`、`黄袋红提`；两类颜色同时存在时显示 `白印黑 / 白袋黑提`。
- 机器计数只能显示为动作 / 周期计数，不得显示为合格产量、库存或计费数量。
- 关键动作在 `1024x768` 和 `390x844` 首屏或合理工作区内可达，长文本不得覆盖控件。

#### UI 重构边界

1. 订单录入以 `screenshots/ui-refactor-audit-2026-07-12/09-gpt-order-entry-final-candidate.png` 为精确视觉基准，先完成该页，不同时改其他模块主题。
2. 表格只保留一个 `订单类型` 列；定制印刷复杂字段在选中行详情区编辑，不重新增加独立“是否印刷”列。
3. 默认选中第 3 行，保证定制印刷详情、校验项定位和库存复核流程可见。
4. 删除行、新建订单丢弃草稿必须确认；校验项必须能定位并高亮对应行；所有编辑单元格必须有键盘焦点环。
5. 库存状态保留可见文本，颜色仅作辅助；桌面和手机均不得用隐藏关键字段换取表面整齐。
6. 订单录入验收后，按“订单池 -> 库存 -> 出库 -> 待办 -> 对账 -> 角色工具”顺序复用组件，不一次性重写全部 CSS。
