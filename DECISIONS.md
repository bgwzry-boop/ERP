- 2026-08-04: ERP is the sole authority for editing, reviewing, and publishing standard, customer-specific, print, special-requirement, and supported special-size prices. The customer Miniapp uses an independently stored BFF replica of one complete ERP price release rather than a live ERP lookup. Each release has a stable version, effective time, change summary, complete payload, and integrity digest. The BFF stages, validates, and atomically activates it; only a successfully activated release may activate its same-version price announcement. Failure leaves the previous release active and suppresses the new announcement. Client totals are untrusted, stale carts are repriced and require reconfirmation, submitted orders lock immutable price/version evidence, and restoring an old price creates a new version. Office review cannot arbitrarily reprice a rule-valid order.
- 2026-08-04: A special size inside the ERP-published supported dimension/material/process/rule envelope is automatically priced and may be submitted directly as an order with the price rule version locked. Only out-of-range, missing-rule, or unconfigured material/process requests enter manual inquiry; acceptance creates a separate order. Online payment is not required for transaction price locking, and settlement remains in ERP statements/payment.
- 2026-08-04: The customer Miniapp and ERP retain separate databases. The Miniapp BFF transaction owns the customer order, line evidence, locked ERP price release, artwork consumption, idempotency response, initial status, and ERP Outbox. A dedicated HTTPS server-to-server ERP adapter uses a unique HMAC-SHA256 key pair, bounded timestamps, durable one-use nonces, the exact request-body digest, and constant-time signature comparison; it preserves the `WT...` source order number and canonical payload digest, verifies the active ERP price release, and creates only an intake envelope, review draft, line mappings, snapshots, and office todo. ERP exposes a separate HMAC-protected, bounded, single-snapshot reconciliation export containing only identifiers, digests, public status, confirmed amount, and frozen SKU/quantity evidence. Formal ERP orders, reservations, production, packing, and fulfillment remain exclusive to office confirmation. The ERP-side Miniapp code is an internal intake/read/reconciliation boundary, not a second public BFF or direct shared-database path.
- 2026-08-04: Miniapp print artwork crosses the separate-database boundary by ERP pull, never by sharing object-storage credentials or exposing storage keys. The frozen order line carries the consumed clean file ID plus immutable file name, MIME, byte length, and SHA-256. ERP uses a third, distinct one-time HMAC credential to request the exact source order/line/file; the Miniapp serves only the still-current versioned clean object and audits the transfer. ERP recomputes length and digest, stores its own attachment, and links it to the draft line through a leased retry job. Any non-succeeded transfer blocks formal order confirmation in the database; an exhausted job creates an office todo, while later success closes it. Order-intake, price-publication, and artwork-transfer HMAC secrets must never be reused.
